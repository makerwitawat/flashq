## 0. เช็คก่อน
- ไม่มี subagent `flash-worker` → หยุด บอก "ใช้ได้ใน opencode เท่านั้น"
- `$ARGUMENTS` ว่าง → ถาม user ว่างานอะไร (question tool)
- อ่าน `.flash.json` ที่รากโปรเจกต์ (ถ้ามี): `main_branch` (ไม่ตั้ง = ตรวจจาก `git symbolic-ref --short refs/remotes/<remote>/HEAD` หรือ `origin/main`/`origin/master` ที่มีจริง) · `remote` (`origin`) · `rules` (กติกาเพิ่มของโปรเจกต์ — ทำตาม)
- **`$ARGUMENTS` มี path แผน `.md` + เลขงาน (เช่น `T-01..T-05`) → โหมดแผน** ไม่งั้นโหมดงานเล็ก

## โหมดแผน (Claude วางแผน+ตรวจให้แล้ว — ห้ามคิดใหม่ ห้ามแก้เนื้องาน)
0. **ซิงก์ (คำสั่งเดียว · ห้ามสืบค้นเองถ้าล้ม)**: `git rev-parse --show-toplevel; git branch --show-current; git fetch <remote> <main_branch>; git merge --no-edit <remote>/<main_branch>` แล้วเช็คว่าไฟล์แผนมีอยู่
   - อยู่ใน `.claude/worktrees` หรือ branch ≠ `<main_branch>` → **หยุด** บอกให้เปิด opencode ที่ checkout หลัก
   - merge ล้ม → `git merge --abort` (ถ้ามี MERGE_HEAD) → **หยุด** บอกบรรทัดสำคัญของ git · **ห้าม rebase/reset**
   - ไม่พบแผน → **หยุด** "ไม่พบแผน — ให้ Claude push แผนก่อน" (ห้ามค้นที่อื่น)
1. อ่าน §0 กติกา + บล็อกงานที่ระบุ (Grep หัว `T-xx` → Read เฉพาะช่วง) · งานที่ติ๊ก `[x]` แล้ว → ข้าม · เลขงานไม่มีในแผน → **หยุด**
2. ทีละงานตามลำดับ: ส่ง `flash-worker` ด้วย brief = `กติกา: <§0 ทั้งข้อ>` + `งาน: <บล็อก T-xx ตรงตัว — รวมบรรทัด skill: ถ้ามี worker โหลดเอง ห้ามตัดทิ้ง>` + "แผนนี้อนุญาต commit 1 งาน = 1 commit ตาม §0 · ห้าม push"
3. ได้ `DONE` → เช็คเบา: `git show --stat HEAD` แตะเฉพาะไฟล์ของงาน + ข้อความ commit มี `T-xx` + (งานมีบรรทัด `skill:`) รายงานมี "skill ที่โหลด" ตรงชื่อ — ไม่ตรง/เป็น `-` = จดต่อท้ายช่อง "ผล" ของแถว §4 (ไม่ถึงกับตก) → ติ๊ก `[x]` + เติมแถว §4 (ผล · hash · **หลักฐานชี้ขาด = path log + บรรทัด/ค่าตรงตัว** (งาน `แบบ: เทสต์ก่อน` = ต้องมีทั้ง log แดงและเขียว · ขาด log แดง = ไม่ติ๊ก ถือเป็น `FAIL`) · ช่อง "ตรวจ Claude" เว้นว่าง) → งานถัดไป · **ห้ามรันเทสต์/build ซ้ำเอง** (แค่เปิดไฟล์หลักฐานดูว่ามีจริง)
4. `FAIL` / `⛔` / แตะไฟล์เกิน → บันทึก §4 แล้ว **หยุดทั้งชุด** · `FAIL: quota` → บอก "บัญชีโควตาหมด" แล้วหยุด (flashq สลับบัญชีให้ได้)
5. จบ: commit การแก้แผน (§4/ติ๊ก) เฉพาะไฟล์แผน (`git add -- <แผน>` + `git commit`) · **ห้าม push** · สรุปสั้น + "กลับไป Claude Code ตรวจด้วย `/flash-check <แผน>`"

## โหมดงานเล็ก
- ไม่เหมาะ (ต้องออกแบบเอง · หาต้นตอบั๊ก · review · แก้ > 3 ไฟล์ · ไม่รู้ว่าแก้ไฟล์ไหน) → **ปฏิเสธพร้อมเหตุผล**
- เตรียม brief เอง (grep/read แบบ offset/limit): `เป้าหมาย` · `ไฟล์ที่แก้ได้ (≤3)` · `ข้อเท็จจริง/โค้ดที่ตัดมา ±10 บรรทัด` · `ขั้นตอน` · `คำสั่งยืนยัน` · `skill: <ชื่อ>` (ถ้าตาราง routing ใน `AGENTS.md`/`CLAUDE.md` ของโปรเจกต์ชี้ skill ที่ตรงงาน — ใส่เฉพาะชื่อ ไม่ต้องเปิด SKILL.md) → ส่ง `flash-worker`
- รับผล: `FAIL` เพราะ brief → แก้ส่งใหม่ได้ 1 ครั้ง · `DONE` → `git diff` ต้องแตะเฉพาะไฟล์ใน brief + รันคำสั่งยืนยันซ้ำเอง
- สรุป: สถานะ · ไฟล์ที่แก้ · ผลคำสั่งยืนยัน · **ยังไม่ commit** (รอ user)
