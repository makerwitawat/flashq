1. ทำทีละงานตามลำดับ · **1 งาน = 1 commit** (`git add -- <ไฟล์ของงาน>` + `git commit -m "<ข้อความในงาน>"` หรือคำสั่ง commit ของโปรเจกต์: <...>) · **ห้าม push**
2. แก้เฉพาะไฟล์ในช่อง "ไฟล์" ของงานนั้น · ห้าม refactor/จัดรูปแบบ/แก้ comment/แปลง encoding
3. **เลขบรรทัดอาจเลื่อน** → หาจากข้อความใน "ก่อน" (Grep) · หาไม่เจอ/เจอหลายที่/ไม่ตรง → **หยุด ⛔** บันทึกใน §4
4. รันคำสั่งยืนยันของแต่ละงาน **ครั้งเดียว** ตามที่เขียนไว้ตรงตัว · FAIL → rerun 1 ครั้ง · ยังไม่ผ่าน = ⛔ หยุด
5. จบแต่ละงาน → ติ๊ก `[x]` + เติมแถว §4 (ผล · commit · **หลักฐานชี้ขาด = path log/ไฟล์ผล + บรรทัด/ค่าที่แผนกำหนด ตรงตัว**) — Claude ตรวจจากหลักฐานนี้ ไม่รันซ้ำ · หลักฐานไม่ครบ = งานไม่จบ
6. **ห้ามแตะ**: <ไฟล์/โฟลเดอร์ต้องห้าม>
7. **งานแบบ "เทสต์ก่อน"** (มีบรรทัด `แบบ: เทสต์ก่อน`) ทำตามลำดับนี้เท่านั้น: เขียนเทสต์ → รัน **ก่อนแก้โค้ด** ต้อง FAIL ด้วยเหตุที่แผนบอก (เก็บ log "แดง") → แก้โค้ด → รันซ้ำต้อง PASS (เก็บ log "เขียว") → commit เดียว · เทสต์ผ่านตั้งแต่ก่อนแก้ / ล้มด้วยเหตุอื่น (เช่น compile error, import ไม่เจอ) → **⛔ หยุด** (เทสต์ไม่ได้วัดสิ่งที่ต้องแก้) · ห้ามแก้เทสต์ให้ผ่านแทนการแก้โค้ด
8. **ห้ามรายงานด้วยคำเดา** — "น่าจะผ่าน" "ควรจะใช้ได้" "แก้นิดเดียวไม่ต้องรัน" "เทสต์นี้ไม่เกี่ยว" "ข้ามไปก่อน" = งานยังไม่จบ · ไม่ได้รันจริง = เขียนว่า "ไม่ได้รัน" ตรง ๆ
