อินพุต: $ARGUMENTS · เป็น path `GOAL_*.md` ที่มีอยู่ → **ทำต่อ** (ข้อ 5) · เป็นข้อความ → เป้าหมายใหม่ (ข้อ 1) · ว่าง → หา `GOAL_*.md` ใน `<plan_dir>` ที่ยังไม่ DONE แล้วถาม user (AskUserQuestion)

คุณ = **เจ้าของเป้าหมาย**: เขียนธงที่วัดได้ → วางแผน → ส่ง Flash → ตรวจ → วนจนผ่าน · **ห้ามแก้โค้ดเอง** (ยกเว้นเขียนเทสต์เกณฑ์ในข้อ 1) · ตัดสินผ่าน/ไม่ผ่านจาก `flashq goal verify` เท่านั้น ห้ามตัดสินเองว่า "น่าจะตรงความต้องการแล้ว"

## 1. ตั้งธง (ครั้งเดียว)
- ค่าโปรเจกต์ตาม `/flash-plan` §0 (`.flash.json` · ไม่มี → `python {{FLASHQ}}/flashq.py init --install --commit`)
- สำรวจพอให้รู้ว่า "ผ่าน" วัดด้วยอะไร: เทสต์/build/สคริปต์ที่มีอยู่ก่อน · ไม่มี → **เขียนเทสต์เกณฑ์เอง** (acceptance test เล็ก ๆ ที่ตอนนี้ต้อง FAIL) แล้วใส่ใน `goal-locked:`
- คัดลอก `{{FLASHQ}}/templates/GOAL_TEMPLATE.md` → `<plan_dir>/GOAL_<เรื่อง ASCII>.md` เติมครบ:
  - ความต้องการ = คำ user ตรงตัว
  - เกณฑ์ G-xx: ทุกข้อมี `ตรวจ:` (คำสั่ง · exit 0 = ผ่าน · `ต้องเห็น:` ถ้า exit 0 ไม่พอ) หรือ `คนตรวจ:` (เฉพาะสิ่งที่เครื่องวัดไม่ได้จริง)
  - คำลอย ๆ ของ user ("เร็วขึ้น", "สวย") → แปลงเป็นตัวเลข/ข้อความที่วัดได้ หรือ `คนตรวจ:` · แปลงไม่ได้ → ถาม user
  - `goal-files:` ให้แคบที่สุดที่งานต้องแตะ · `goal-locked:` = เทสต์เกณฑ์ · งบรอบ/ชั่วโมง (ค่าเริ่มต้น 5 รอบ / 6 ชม.)
- **ตัวตรวจข้อจำกัด**: `python {{FLASHQ}}/flashq.py goal check <GOAL>` → `ต้องแก้:` ทุกข้อต้องแก้จน `GOAL_CHECK=OK` · `เตือน:` พิจารณาแก้ (บอก user ในข้อถัดไป)
- **ถาม user ครั้งเดียว** (AskUserQuestion): สรุปเกณฑ์ + ขอบเขต + งบ + คำเตือนที่เหลือ → "เริ่มวน (แนะนำ)" / "แก้เกณฑ์" / "ยกเลิก"
- commit เฉพาะไฟล์ GOAL + เทสต์เกณฑ์ แล้ว push ตามกติกา `/flash-plan` §3

## 2. หนึ่งรอบ
1. **แผน**: ทำตาม `/flash-plan` §0–§3 (รวม §2.5 เลือกรุ่น) โดยงานของแผน = **เกณฑ์ที่ยังไม่ผ่าน** (รอบแรก = ทุกข้อ) · ชื่อแผน `PLAN_FLASH_<เรื่อง>_R<n>.md` · ทุกงาน T-xx ต้องอยู่ใน `goal-files:` และ DoD ใส่คำสั่ง `ตรวจ:` ของเกณฑ์ที่งานนั้นรับผิดชอบ · ข้อที่ "ถอยหลัง" (เคยผ่าน) แก้ก่อน · **คนเขียนแผนไม่รันเกณฑ์/ทำต้นแบบเอง** (รอบแรก = ถือว่าทุกข้อยังไม่ผ่าน · รอบถัดไปใช้ท้าย output ของ `goal verify`) ตามกติกา `/flash-plan` §1 · งบ ~20 นาที
   - **รอบ 2 ขึ้นไป = แผนแก้ส่วนที่ตกเท่านั้น** (`_R<n>` สั้น · งบ ~10 นาที): อ่านแค่ท้าย output เกณฑ์ที่ตก (`goal verify`) + §4 บันทึกผล/⛔ ของแผนรอบก่อน + file:line ที่เกี่ยว · **ห้ามอ่านโค้ดทั้งระบบใหม่ ห้ามเขียนงานที่ผ่านแล้วซ้ำ ห้ามคัดแผนรอบก่อนมาทั้งไฟล์** · งานเดิมที่ยังไม่ทำ/⛔ อ้างถึงแผนรอบก่อน (`ตาม T-xx ใน _R<n-1>`) แทนการเขียนใหม่
2. **ส่ง**: `/flash-plan` §4 (background · ไม่ poll · รอแจ้งจบ)
3. **ตรวจงาน**: `/flash-check` §0–§3 + บันทึกช่อง "ตรวจ Claude" ใน §4 ของแผน — **ข้าม §4 วนอัตโนมัติ/merge+push และ §5** (การวนเป็นหน้าที่ของคำสั่งนี้)
4. **ตัดสิน**: `python {{FLASHQ}}/flashq.py goal verify <GOAL>` (รันที่ checkout หลัก · timeout ≥ จำนวนเกณฑ์ × goal-cmd-timeout-min) → อ่านบรรทัด `GOAL=`
   - `ไม่มีงานใหม่ตั้งแต่รอบ n` = verify ซ้ำโดยไฟล์/งาน Flash ไม่เปลี่ยน → แทนผลรอบเดิม ไม่นับรอบ (อย่า verify วนรอผลเปลี่ยน — ต้องมีงานใหม่ก่อน)
   - `เตือน: ไฟล์นอกขอบเขตที่อาจเป็นของ session อื่น` = ไม่เบรก แต่ดู `git log`/`git status` ว่าเป็นของงานนี้จริงไหม · เป็นของงานนี้ → รายงาน user เหมือนหลุดขอบเขต
5. เติมแถวใน "บันทึกรอบ" ของ GOAL (รอบ · แผน · งาน · GOAL= · ไม่ผ่าน · หมายเหตุ) แล้ว commit เฉพาะไฟล์ GOAL

## 3. ผลของ verify
- `GOAL=DONE` → สรุปให้ user (รอบที่ใช้ · commit ของแต่ละรอบ) · **ไม่ push เพิ่มเอง** ถาม user ก่อน
- `GOAL=DONE_NEEDS_USER` → เครื่องตรวจผ่านหมด · `goal status` ก่อน (user อาจกด ✅/❌ ในหน้าเว็บแล้ว = บรรทัด `คนตรวจ G-xx:`) · ข้อที่ยังไม่มีผล → ถาม user (AskUserQuestion: ผ่าน (แนะนำ) / ไม่ผ่าน + เหตุ) แล้วบันทึก `python {{FLASHQ}}/flashq.py goal human <GOAL> G-xx --pass` หรือ `--fail "เหตุ"` (ผ่านครบ = `GOAL=DONE`) · ไม่ผ่าน → แปลงเหตุเป็นเกณฑ์ที่วัดได้ → user ยืนยัน → `goal check --reset` → วนต่อ
- `GOAL=CONTINUE` → รอบถัดไปทันที (ข้อ 2) ใช้ output ที่ล้มเป็นหลักฐานในแผน · ไม่ต้องถาม user
- `GOAL=STOP` → **หยุดวน** รายงานบรรทัด `เบรก:` ทุกข้อ + สิ่งที่ลองไปแล้ว + ทางเลือก (AskUserQuestion) · ห้ามแก้ GOAL/งบเพื่อให้วนต่อเอง
  - พังซ้ำเรื่องเดิม → เสนอ `/flash-investigate` หาต้นตอก่อน · หลุดขอบเขต/แก้ไฟล์ล็อก → ให้ user ดู diff ก่อน (ห้าม revert เอง) · ครบงบ → สรุปว่าขาดอะไร

## 4. เบรกที่คุณต้องหยุดเอง (นอกจากที่ flashq ตรวจ)
- ต้องตัดสินใจเชิงออกแบบ/เลือกทาง หรือความต้องการกำกวม → ถาม user
- แผนต้องแตะไฟล์นอก `goal-files:` → ถาม user ขยายขอบเขต (ห้ามแก้ GOAL เงียบ ๆ — flashq จะ STOP เพราะเกณฑ์ถูกแก้)
- `FLASH_RUN=QUOTA` (สลับครบแล้ว) / `NOSTART` ซ้ำ / `BUSY` → หยุด รายงาน
- งานรอบนี้ไม่มีเกณฑ์ไหนขยับเลยและ Flash รายงาน ⛔ → อย่าส่งแผนเดิมซ้ำ ให้สืบต้นตอก่อน

## 5. ทำต่อ (session ปิด/บริบทยาว)
- `python {{FLASHQ}}/flashq.py goal status <GOAL>` → รอบที่ใช้ · ผลล่าสุด · ผลคนตรวจ · แล้วอ่าน "บันทึกรอบ" ใน GOAL (user อาจกด "ตรวจใหม่"/✅❌ ในหน้าเว็บ flashq ไปแล้ว — ผลล่าสุดใน status คือของจริง)
- ผลล่าสุดเป็น `DONE_NEEDS_USER` ที่มีคนตรวจ ❌ → แปลงเหตุเป็นเกณฑ์ (ข้อ 3) · เป็น `STOP` → รายงานเบรกให้ user ก่อน แล้วถาม (AskUserQuestion) ว่าจะ verify ใหม่ / แก้ตามทางเลือกในข้อ 3
- มีงาน flashq ค้างอยู่ (`python {{FLASHQ}}/flashq.py`) → รอจบแล้วไปข้อ 2.3 · ไม่มี → ข้อ 2.4 ก่อน (ตัดสินสถานะจริง) แล้ววนต่อ
- บริบทยาว (≥3 รอบใน session เดียว) → จบรอบปัจจุบัน แล้วแนะนำ user เปิด session ใหม่ด้วย `/flash-goal <path GOAL>`
