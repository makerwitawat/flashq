ชุดที่ต้องการ: $ARGUMENTS · ว่าง → ชุดเดียวที่ตั้งไว้ (ถ้ามีหลายชุดต้องระบุ)

## 1. หลักการ (ทำไมเชื่อผลนี้ได้)
- Flash **แก้ไฟล์จริงใน checkout** แต่ได้เฉพาะไฟล์ที่ชุดนั้นอนุญาต (`doc.presets.<ชื่อ>.paths`) — **flashq ตัดสินเองด้วยกลไก** (git/ไฟล์จริง) ไม่เชื่อคำบอก "แก้เสร็จแล้ว" ของโมเดล
- fail-closed: ผ่านได้ทางเดียวคือ **DRAFT** (ร่างที่ผ่านด่านกลไกครบ รอคุณดู diff) · ผลอื่นทั้งหมดไม่ผ่าน:
  - `OUTSIDE` แตะไฟล์นอกขอบเขต (หรือ `.env`/`.flash.json`/`.git`) · `SECRET` พบข้อความคล้ายรหัสผ่าน/โทเค็นในส่วนที่เพิ่ม → **flashq ย้อนไฟล์ให้ทันที**
  - `BADREF` เอกสารอ้างไฟล์/บรรทัดที่ไม่มีจริง · `DELETED` ลบไฟล์ · `UNCHECKED` ตรวจเนื้อหาไม่ได้ (ไบนารี/ใหญ่เกิน) · `CHANGED` HEAD เปลี่ยนระหว่างรัน · `NOCHANGE` ไม่มีไฟล์เปลี่ยน · `TIMEOUT`/`ERROR` → **เก็บไฟล์ไว้ให้ดู** (ไม่ย้อนเอง) แล้วรอคุณทิ้ง
- **ไม่ commit ให้เลย** · ช่างเอกสารไม่รันคู่กับงานที่แก้ไฟล์/นักทดสอบ/ช่างเอกสารอื่นของโปรเจกต์เดียวกัน (ตัวจัดคิวกันให้ — ไม่งั้นแยกไม่ออกว่าใครแก้ไฟล์ไหน)
- ขอบเขตมาจาก `.flash.json` เท่านั้น — หน้าเว็บเลือกได้แค่ "ชื่อชุด" · `paths` กว้างเกินไป (`**`, `*`) หรือครอบไฟล์ต้องห้ามจะถูกปฏิเสธตั้งแต่เริ่ม

## 2. เตรียมชุดเอกสาร (ครั้งแรกของโปรเจกต์)
ใน `.flash.json` ของโปรเจกต์ (ผู้ใช้ยืนยันก่อนเพิ่ม — ห้ามเดา paths เองโดยไม่บอก):
```json
{"doc": {"presets": {
  "docs": {"paths": ["README.md", "CHANGELOG.md", "docs/**"], "brief": "เอกสารเป็นภาษาไทย · CHANGELOG เพิ่มบรรทัดใหม่ด้านบนตามรูปแบบเดิม", "timeout_min": 30}
}}}
```
- `paths` = glob ของไฟล์ที่แก้ได้ (เทียบจากรากโปรเจกต์ · ไม่เกิน 32 รายการ) · `brief` = โจทย์เพิ่มเติม (ไม่เกิน 4000 ตัวอักษร) · `timeout_min` (ค่าเริ่มต้น 30)

## 3. สั่งงาน
```
{{FLASHQ_RUN}} doc [ชุด] [--since <commit/tag>] [--project "<path>"]
```
- ไม่ระบุ `--since` = เทียบโค้ดตั้งแต่ครั้งล่าสุดที่คุณ "รับ" ร่างของชุดนี้ · ไม่เคย = ให้ Flash ดูประวัติล่าสุดเอง
- รันใน background (`run_in_background: true` คำสั่งเดียวตรง ๆ — ห้าม `&` · sleep · head/tail · ยาม `run_guard.py` บล็อก) · รอผล: `{{FLASHQ_RUN}} wait <job>` (ไม่ต้อง sleep/poll)

## 4. ตรวจก่อนรายงานผู้ใช้ (ห้ามเชื่อสรุปของ Flash ตรง ๆ)
1. `{{FLASHQ_RUN}} log <job>` — คำตัดสินของ flashq + ไฟล์ที่เปลี่ยน
2. `git diff` ของโปรเจกต์ (ไฟล์ใหม่ดู `git status`) — **อ่านเอกสารที่แก้เทียบกับโค้ดจริง** · ข้อที่อ้างโค้ด เปิดไฟล์ที่อ้างตรวจเอง (flashq ตรวจแค่ว่าไฟล์/บรรทัดมีจริง ไม่ได้ตรวจว่าเนื้อหาถูก)
3. รายงานผู้ใช้เป็นภาษาไทย: **แก้ไฟล์ไหน · ตรงกับโค้ดหรือไม่ (ถูก/ผิดตรงไหน) · ควรรับหรือทิ้ง**

## 5. ตัดสินร่าง (เฉพาะเมื่อผู้ใช้สั่ง — ห้ามตัดสินเอง)
- รับ: `{{FLASHQ_RUN}} doc-review <job> accept` — เก็บไฟล์ไว้ (ยังไม่ commit · ผู้ใช้ commit เอง) · รับได้เฉพาะ DRAFT
- ทิ้ง: `{{FLASHQ_RUN}} doc-review <job> discard` — ย้อน **เฉพาะไฟล์ที่ช่างเอกสารแตะ** (งานค้างอื่นของผู้ใช้ไม่ถูกแตะ) · ปฏิเสธถ้า HEAD เปลี่ยนแล้ว หรือไฟล์ถูกแก้ต่อหลังช่างเอกสารจบ (`--force` ยืนยันทับ)
- หน้าเว็บ `flashq ui` มีปุ่มดู diff / รับ / ทิ้ง บนการ์ดงานเอกสาร
