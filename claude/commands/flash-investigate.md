บรีฟ: $ARGUMENTS · ว่าง → ถาม user (AskUserQuestion) ว่าให้สืบเรื่องอะไร

## 1. เขียนบรีฟให้ครบ (ผู้สืบเห็นแค่บรีฟ ไม่เห็นบทสนทนา)
- **อาการ** ที่เห็นจริง (ข้อความ error / พฤติกรรมที่ผิด / ขั้นตอนทำซ้ำ)
- **โมดูล/ไฟล์ที่น่าจะเกี่ยว** (ถ้ารู้) และสิ่งที่ตัดทิ้งแล้ว
- **สิ่งที่ต้องคืน**: ต้นตอ + `ไฟล์:บรรทัด` เป็นหลักฐาน + ระดับความมั่นใจ · **ห้ามแก้ไฟล์**

## 2. ส่งงาน (อ่านอย่างเดียว ไม่ชนงานอื่นในคิว)
```
python {{FLASHQ}}/flashq.py investigate "<บรีฟ>" --project "<path โปรเจกต์>" --auto
```
- ใช้ `--project` ถ้าไม่ได้อยู่ในโปรเจกต์นั้น · บรีฟหลายบรรทัดใส่ในเครื่องหมายคำพูดได้
- ต้องมี agent `flash-investigator` (มาจาก `flashq.py install`) ไม่มี/เป็น subagent → flashq จะรายงาน `FAIL` พร้อมคำแนะนำ

## 3. อ่านผล
- `FLASH_RUN=OK` → อ่านรายงานจาก log (`python {{FLASHQ}}/flashq.py log <job>`)
- `FAIL` / `TIMEOUT` / `QUOTA` → บอก user ตามจริง ห้ามเดาผลเอง

## 4. ตรวจก่อนเชื่อ (สำคัญ)
- **ห้ามเชื่อผลโดยไม่เปิดดูโค้ดจริง**: เปิด `ไฟล์:บรรทัด` ที่ผู้สืบอ้างทุกจุด ตรวจว่าตรงและอธิบายอาการได้จริง
- ต้นตอที่ยืนยันแล้วค่อยสรุปให้ user / เขียนแผนแก้ · ที่ยังไม่แน่ใจให้บอกว่า "ยังไม่ยืนยัน"
