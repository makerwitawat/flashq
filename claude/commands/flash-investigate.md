บรีฟ: $ARGUMENTS · ว่าง → ถาม user (AskUserQuestion) ว่าให้สืบเรื่องอะไร

เช็กความสดก่อนเริ่ม (อ่านอย่างเดียว): `{{FLASHQ_RUN}} install --check` → `INSTALL=STALE` = คำสั่งที่ใช้อยู่เป็นฉบับเก่า → บอก user หนึ่งบรรทัดให้รัน `install` ตามที่ flashq พิมพ์ (ได้ผลใน session ใหม่) แล้วสืบต่อได้ · `INSTALL=OK` = เงียบ

## 1. เขียนบรีฟให้ครบ 4 ช่อง (ผู้สืบเห็นแค่บรีฟ ไม่เห็นบทสนทนา · บรีฟคือหัวใจ — ผิดจุดตั้งแต่ต้นผลก็ผิดทั้งชุด)
1. **อาการ** — สิ่งที่เห็นจริงตรงตัว: ข้อความ error / ค่าที่ได้ vs ที่ควรได้ / ขั้นตอนทำซ้ำ (copy มาเอง ห้ามสรุปตามความเข้าใจ)
2. **จุดที่น่าจะเกี่ยว** — โมดูล/ไฟล์/ฟังก์ชันที่รู้แล้ว (ไม่รู้ = เขียนว่าไม่รู้ ห้ามเดาใส่)
3. **ที่ตัดทิ้งแล้ว** — สิ่งที่ลองแล้ว/พิสูจน์แล้วว่าไม่ใช่ (กันวนซ้ำ) และบั๊กเก่าที่คล้ายกัน
4. **สิ่งที่ต้องคืน** — ต้นตอ 1 ประโยค + `ไฟล์:บรรทัด` พร้อมโค้ดที่คัดตรงตัว + วิธีพิสูจน์ + ระดับมั่นใจ · **ห้ามแก้ไฟล์**

ก่อนส่ง ตรวจเอง: (ก) ข้อ 1 มีของจริงที่ copy มา ไม่ใช่คำอธิบายกว้าง ๆ (ข) ไม่มีข้อสันนิษฐานของคุณปนเป็นข้อเท็จจริง — ถ้ามีให้ติดป้าย "(สมมติฐาน)" (ค) ผู้สืบทำตามบรีฟนี้ได้โดยไม่ต้องถามกลับ
ถ้าบรีฟไม่พอ ผู้สืบจะตอบ `บรีฟไม่พอ: ขาด …` → เติมแล้วส่งใหม่ (ห้ามถือเป็นผลสืบ)

## 2. ส่งงาน (อ่านอย่างเดียว ไม่ชนงานอื่นในคิว)
```
{{FLASHQ_RUN}} investigate "<บรีฟ 4 ช่อง>" --project "<path โปรเจกต์>" --auto
```
- ใช้ `--project` ถ้าไม่ได้อยู่ในโปรเจกต์นั้น · บรีฟหลายบรรทัดใส่ในเครื่องหมายคำพูดได้ · รันใน background (`run_in_background: true` คำสั่งเดียวตรง ๆ — ห้าม `&` · sleep · head/tail · ยาม `run_guard.py` บล็อก)
- ต้องมี agent `flash-investigator` (มาจาก `flashq.py install`) ไม่มี/เป็น subagent → flashq จะรายงาน `FAIL` พร้อมคำแนะนำ
- โควตาหมด → flashq ย้าย provider เป็นโมเดลเดิมให้เอง (ค่าเริ่มต้น 2 ครั้ง)
- **บั๊กกำกวม / เคยแก้แล้วไม่หาย → สืบ 2 session** (อีกตัวใส่ `--model` คนละโมเดล/คนละตระกูล) แล้วเทียบ `file:line` ต้องตรงกัน

## 3. อ่านผล
- `FLASH_RUN=OK` → อ่านรายงานจากท้ายผลลัพธ์ (หรือ `{{FLASHQ_RUN}} log <job>`) · `FLASH_RUN=OK_UNVERIFIED` = ผู้สืบอ้างผิด/ไม่อ้างเลขบรรทัด → ห้ามเชื่อจนกว่าจะเปิดโค้ดยืนยัน
- `FAIL` / `TIMEOUT` / `QUOTA` → บอก user ตามจริง ห้ามเดาผลเอง · **ห้ามไล่โค้ดสืบเองแทน (กินโควตา Claude ทั้งที่โควตา DeepSeek มากกว่ามาก)** → ส่งผู้สืบรอบใหม่ตาม "บันไดสืบซ้ำ" ด้านล่างเลย ไม่ต้องถาม user · ถามได้เฉพาะเมื่อบันไดหมดแล้ว (ข้อ 4 ของบันได)
- บรรทัด `CITATIONS: ตรงถึงโค้ด N · ตรงแค่ไฟล์/บรรทัด K · ผิด M · ตรวจไม่ได้ U · เลขเพี้ยน D` (flashq ตรวจกลไกว่า `ไฟล์:บรรทัด` ที่อ้างมีจริง · "ตรงถึงโค้ด" = โค้ดที่คัดไว้อยู่ในบรรทัดนั้นจริง · "ตรงแค่ไฟล์/บรรทัด" = ผู้สืบไม่ได้คัดโค้ดมา → **ส่งผู้สืบรอบใหม่ให้คัดโค้ดจุดนั้นมา** ไม่ใช่ Claude เปิดดูเอง) → ข้อที่ ✗ (ผิด) = **ห้ามเชื่อข้อนั้น** · ↕ (เลขเพี้ยน) = ใช้เลขบรรทัดที่ถูกแทน · ? (ตรวจไม่ได้) = ส่งผู้สืบรอบใหม่ให้อ้าง path เต็ม (เฉพาะข้อที่เป็นข้อสรุปหลัก) · ผ่านครบแปลว่า "อ้างตรงโค้ดจริง" เท่านั้น ยังไม่ได้แปลว่าเป็นต้นตอ

## 3.5 ผลสืบไม่พอ = สืบใหม่ (วนได้ไม่จำกัดจนพอ ไม่ต้องถาม user)
เช็กลิสต์ 6 ข้อ — ขาดข้อไหน/กำกวม/CITATIONS ผิด = **ส่งผู้สืบรอบใหม่ทันที** โดยใส่ข้อที่ขาดเข้า "สิ่งที่ต้องคืน" ของบรีฟ:
1. มี `ไฟล์:บรรทัด` ของจุดต้นตอ
2. มีโค้ด "ก่อน" คัดตรงตัว (CITATIONS ตรงถึงโค้ด)
3. มีเหตุผล/หลักฐานว่าทำไมจุดนั้นอธิบายอาการได้
4. มีคำสั่งตรวจที่รันได้จริง
5. ตัวเลข/ค่าที่อ้างมาจากการนับ/รันจริง ไม่ใช่ประมาณ
6. CITATIONS ไม่มี ✗ (ผิด) ในข้อสรุปหลัก · ? ในข้อสรุปหลัก = ขอ path เต็ม

**บันไดเมื่อวนเดิมไม่คืบ** (รอบใหม่ได้ผลเท่าเดิม/ขาดข้อเดิม):
1. บีบบรีฟให้แคบลง (เหลือโมดูล/ฟังก์ชันเดียว) แล้วสืบใหม่
2. เปลี่ยน `--model` เป็นคนละโมเดล/คนละตระกูล
3. แบ่งบรีฟเป็นหลายคำถามย่อย ส่งผู้สืบแยกกัน
4. ยังไม่คืบ → รายงาน user ด้วยรูปแบบ: `ต้องทำเอง: … · ลองแล้ว: … · ขาด: … · ขั้นที่ user ทำ: …` (ข้อนี้เท่านั้นที่หยุดถาม user)

## 4. ตรวจก่อนเชื่อ (สำคัญ)
- **เปิดโค้ดจริงที่ `ไฟล์:บรรทัด` ของข้อสรุปหลัก ≤2 Read** (เฉพาะยืนยันต้นตอหลัก — ห้ามเปิดเพิ่มเพื่อเติมบรีฟ/ไล่หาเอง ขาดอะไร = กลับ §3.5) แล้วเทียบว่าอธิบายอาการได้จริง (flow จากอาการมาถึงจุดนั้น) · ไม่ใช่แค่อ้างตรง
- สองผู้สืบชี้ต่างกัน / มั่นใจระดับกลางหรือต่ำ → ยังไม่ใช่ต้นตอที่ยืนยัน ห้ามเขียนแผนแก้ให้ Flash จากข้อสรุปนี้
- ต้นตอที่ยืนยันแล้วค่อยสรุปให้ user / เขียนแผนแก้ (`/flash-plan`) · ที่ยังไม่แน่ใจให้บอกว่า "ยังไม่ยืนยัน"
