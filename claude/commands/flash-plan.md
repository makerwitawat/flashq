## 0. ค่าโปรเจกต์
- อ่าน `.flash.json` ที่รากโปรเจกต์ (ถ้ามี): `main_branch` (ไม่ตั้ง = ตรวจจาก `git symbolic-ref --short refs/remotes/<remote>/HEAD` หรือ `origin/main`/`origin/master` ที่มีจริง) · `remote` (`origin`) · โปรเจกต์ใหม่ที่ยังไม่มี `.flash.json` → รัน `python {{FLASHQ}}/flashq.py init --install --commit` เองก่อน (ไม่ต้องถาม) หรือเสนอ `/flash-init` · `plan_dir` (`docs/plans`) · `rules`
- อ่าน `AGENTS.md`/`CLAUDE.md` ของโปรเจกต์ → กติกา build/test/commit/encoding ที่ต้องใส่ใน §0 ของแผน

## 1. สำรวจ + ยืนยัน (ห้ามเดา)
- **ต้นตอยังไม่ยืนยัน → ส่งผู้สืบ DeepSeek ก่อน** (ประหยัดโควตา Claude): ใช้ `/flash-investigate` หรือ `python {{FLASHQ}}/flashq.py investigate "<บรีฟ 4 ช่อง>" --auto` (background · อ่านอย่างเดียว) · บั๊กกำกวม/เคยแก้แล้วไม่หาย → สืบ 2 session คนละโมเดล ต้องชี้ file:line ตรงกัน · **Claude เปิดเฉพาะ file:line ที่อ้าง 1–2 จุดเพื่อยืนยันก่อนเขียนแผนแก้** · บรรทัด `CITATIONS ... ผิด` = ข้อนั้นห้ามเชื่อ · ผู้สืบกับผู้แก้ต้องคนละ session
- ทุกจุดแก้ต้องมี: file:line จริง · โค้ด "ก่อน" ตรงตัว (copy จากไฟล์) · เหตุผล/หลักฐานว่าผิด · คำสั่งยืนยันที่รันได้
- ค้นหลายไฟล์ → ส่ง subagent ค้นได้ แต่ผลต้องตรวจซ้ำเองที่ file:line
- ยืนยันไม่ได้ → ใส่เป็นงาน 🟡 พร้อมขั้น "พิสูจน์" หรือย้ายไป §5 นอกแผน — **ห้ามใส่งานเดาให้ Flash แก้**
- **คนเขียนแผนไม่ใช่คนทำงาน** (ถ้าทำเองหมด = เสียโควตา Claude แทน Flash · แผนช้าเป็นชั่วโมง):
  - **ห้ามทำต้นแบบเต็ม** (คัดลอกแอป/โมดูลไปแก้ทั้งชุดใน `.tmp/` แล้วเอา diff มาใส่แผน) · **ห้ามรันเกณฑ์/เทสต์ทั้งชุดเอง** — ผลตกของเกณฑ์ใช้จากท้าย output ของ `goal verify`/log ที่มีอยู่แล้ว
  - ลองได้แค่ **จุดเสี่ยงสั้น ๆ** ที่ไม่ลองแล้วเขียนแผนไม่ได้ (เช่น API ของ library มีจริงไหม · คำสั่ง Blender/Edge headless รันได้ไหม) · สูงสุด 3 ครั้ง · ครั้งละ ≤2 นาที · สคริปต์เล็กใน `.tmp/` · ผลที่ได้ใส่ในแผนเป็นหลักฐาน
  - **งบเวลาเขียนแผน ~20 นาที** (นับจากเริ่มสำรวจ) → ครบแล้วยังไม่ชัด = เขียนแผนจากที่ยืนยันแล้ว ส่วนที่เหลือเป็นงาน 🟡 "พิสูจน์ก่อนแก้" ให้ Flash ทำ หรือย้ายไป §5 · งานใหญ่เกินจะวางให้ครบใน 20 นาที = แบ่งเป็นหลายแผน/หลายรอบ (รอบแรกทำโครง + เกณฑ์ที่ง่ายก่อน)

## 2. ตัดงาน
- 1 งาน = 1 จุดแก้เล็ก (≤3 ไฟล์) + ยืนยัน + ข้อความ commit
- **"หลัง" ตรงตัว เฉพาะจุดแก้เล็ก** (โค้ดใหม่ ≤ ~20 บรรทัด) · โค้ดใหม่ยาว/ฟีเจอร์ใหม่/หน้าจอใหม่ = **สเปก** (จุดเสียบตรงตัว · ชื่อฟังก์ชัน/พารามิเตอร์/ผลลัพธ์ · พฤติกรรม · กรณีขอบ · เทสต์ที่ต้องผ่าน) แล้วให้ Flash เขียนโค้ดเอง — ดูแบบ T-02 ใน template · **ห้ามแปะโค้ดทั้งไฟล์/diff ยาว/ภาคผนวกโค้ด**
- **ขนาดแผน**: ≤400 บรรทัด และโค้ดใน ``` รวม ≤200 บรรทัด (เกิน = `flashq run` เตือน) · >800 บรรทัด หรือโค้ด >400 บรรทัด = **ปฏิเสธ** (ต้องแบ่งแผน หรือ `--big-plan` เมื่อ user อนุญาต)
- งานที่ต้องออกแบบ/เลือกทาง/รอ user → §2 (ห้ามทำเอง) · เรียงให้ build ผ่านได้ทุกงาน · DoD ต่อกลุ่ม
- เทสต์ใน DoD = เร็วแต่ครอบจุดที่แตะ · FAIL → rerun เฉพาะจุดนั้น 1 ครั้ง · ห้ามเริ่มทั้งชุดใหม่
- **บังคับ "หลักฐานชี้ขาด" ทุกงาน** = path log/ไฟล์ผลที่ DeepSeek สร้างตอนรันยืนยัน + บรรทัด/ค่าที่ต้องเห็น + ค่าก่อนแก้ (แยกได้ว่าแก้จริง) — `/flash-check` ตัดสินจากหลักฐานนี้อย่างเดียว ไม่รันซ้ำ · ออกแบบหลักฐานไม่ได้ = ยังไม่พร้อมส่ง

## 2.5 เลือกรุ่นผู้เขียนแผน (คุณภาพ + ประหยัด token ฝั่งผู้สั่ง)
- **งานใหญ่/เสี่ยง** = ≥4 งาน T-xx · ข้ามโมดูล · แตะ logic หลัก/ความปลอดภัย/protocol · ต้นตอยังไม่ยืนยันเต็มที่ → ต้องเขียนแผนด้วย **Opus**
  - session นี้เป็น Opus อยู่แล้ว → เขียนเองตาม §3
  - session ไม่ใช่ Opus (เช่น Sonnet) → **ส่ง subagent ด้วย Agent tool `model: "opus"`** (subagent_type `general-purpose`) ให้ทำ **เฉพาะข้อแรกของ §3 (เขียนไฟล์แผน)** · brief เป็นไทย ใส่: งาน + หลักฐานที่หาไว้แล้ว (file:line + โค้ด "ก่อน" ตรงตัว · อาการ · log · สิ่งที่ลองแล้ว · การตัดสินใจของ user · base commit) + path ไฟล์นี้ให้อ่าน §1–§3 · สั่งว่า **ห้ามแก้ซอร์สโค้ด ห้าม commit/push ห้ามทำ §4 · ห้ามทำต้นแบบเต็ม/รันเกณฑ์ทั้งชุดเอง (ลองได้แค่จุดเสี่ยงตาม §1) · งบเวลา ~20 นาที** · จุดที่ brief ให้ file:line มาแล้ว → Grep ยืนยันบรรทัดนั้น ไม่ต้องอ่านทั้งไฟล์ · Read ใช้ offset/limit · ขาดข้อมูล → หยุดแล้วบอกว่าขาดอะไร · ตอบสั้น: `PLAN=` · `TASKS=` · งานรอ user ตัดสิน · งาน 🟡 · หมายเหตุ
  - ได้ผลแล้ว agent หลักทำข้อที่เหลือของ §3 (ตรวจ `flashq-files:` ไม่เหลือ `<...>` · commit/push) และ §4 เอง (งานกลไก ราคาถูก)
- **งานเล็ก/กลไก** (≤3 งาน ในโมดูลเดียว ต้นตอยืนยันแล้ว หรือทำตามแผนที่มีอยู่) → เขียนเองด้วยรุ่นของ session นี้ ไม่ต้องเรียก Opus
- โปรเจกต์มี planner agent ของตัวเอง (เช่น `.claude/agents/*flash-planner*.md`) → ใช้ตัวนั้นแทน subagent ทั่วไป

## 3. เขียนแผน
- คัดลอก `{{FLASHQ}}/templates/FLASH_PLAN_TEMPLATE.md` → `<plan_dir>/PLAN_FLASH_<เรื่อง>.md` · เติม base commit (`git rev-parse --short HEAD`) + กติกาโปรเจกต์ใน §0
- **เติม `flashq-files:` ใน §0 ทุกครั้ง** = ทุกไฟล์ที่ทุกงาน T-xx จะแตะ (path จากรากโปรเจกต์ · คั่นด้วย `,` · glob ได้ เช่น `Client/Src/UI/*.cpp`) — คิวกลางโหมด auto ใช้ตัดสินว่ารันพร้อมงานอื่นได้ไหม (ไม่เติม = เดาจาก backtick · ดึงไม่ได้ = ต้องรอ) · แผนแตะไฟล์ที่ทุกโมดูลใช้ร่วม (เช่น CMakeLists.txt ระดับราก, Common/, Util/) หรือ build/สคริปต์ทั้งโปรเจกต์ → `flashq-parallel: no` · ห้ามเหลือ placeholder `<...>`
- commit เฉพาะไฟล์แผน + push เข้า `<remote>/<main_branch>` (อยู่ worktree/branch อื่น → merge แล้ว `git push <remote> HEAD:<main_branch>` · **ห้าม rebase**) — ทำตามกติกา commit ของโปรเจกต์ถ้ามี
- **ยืนยัน**: `git fetch <remote> <main_branch>; git merge-base --is-ancestor <hash แผน> <remote>/<main_branch>` ต้อง exit 0

## 4. ส่งเข้าคิวกลาง (อัตโนมัติ)
- รัน **ใน background** ที่โฟลเดอร์โปรเจกต์ (Bash `run_in_background: true` · ไม่ poll):
  `python {{FLASHQ}}/flashq.py run <path แผน> T-01..T-NN --switch-on-quota 4`
  (worktree → ใช้ checkout หลักเอง · ตรวจแผนใน remote · มีงานอื่นทั้งเครื่อง = รอคิว · โควตาหมด = สลับบัญชีแล้วสั่งซ้ำ)
- บอก user สั้น ๆ: จำนวนงาน · งานที่รอ user ตัดสิน · "DeepSeek กำลังทำ — ดูใน opencode desktop session `flash <ชื่อแผน> <งาน>` · ดูคิว `python {{FLASHQ}}/flashq.py` · เสร็จแล้วผมตรวจต่อเอง"
- **ได้แจ้งว่าจบ → เรียก `/flash-check <path แผน>` ทันที** พร้อมบรรทัด `FLASH_RUN=...`
- สำรอง: ให้บรรทัด `/flash <path แผน> T-01..T-NN` ไปวางใน opencode (เปิดที่ checkout หลัก) แล้วกลับมาสั่ง `/flash-check <path แผน>`
