## 0. ค่าโปรเจกต์
- **เช็กความสดของคำสั่งที่ติดตั้ง** (อ่านอย่างเดียว เร็ว): `{{FLASHQ_RUN}} install --check` → `INSTALL=STALE` = คำสั่ง `/flash-*` ที่ใช้อยู่เป็นฉบับเก่ากว่าต้นฉบับ → บอก user หนึ่งบรรทัดว่าให้รันบรรทัด `install` ที่ flashq พิมพ์ (ได้ผลใน session ใหม่) แล้วทำงานนี้ต่อได้ตามปกติ · `INSTALL=OK` = เงียบ ไม่ต้องพูดถึง
- อ่าน `.flash.json` ที่รากโปรเจกต์ (ถ้ามี): `main_branch` (ไม่ตั้ง = ตรวจจาก `git symbolic-ref --short refs/remotes/<remote>/HEAD` หรือ `origin/main`/`origin/master` ที่มีจริง) · `remote` (`origin`) · โปรเจกต์ใหม่ที่ยังไม่มี `.flash.json` → รัน `{{FLASHQ_RUN}} init --install --commit` เองก่อน (ไม่ต้องถาม) หรือเสนอ `/flash-init` · `plan_dir` (`docs/plans`) · `rules`
- อ่าน `AGENTS.md`/`CLAUDE.md` ของโปรเจกต์ → กติกา build/test/commit/encoding ที่ต้องใส่ใน §0 ของแผน
- **หา skill ของโปรเจกต์ (ครั้งเดียวตอนเริ่ม · ราคาถูก · ไม่เปิด `SKILL.md`)** เพื่อใส่บรรทัด `skill:` ต่องานใน §3: ① `AGENTS.md`/`CLAUDE.md` มีตาราง routing (งาน → skill เช่น "Skill Routing") → ใช้ตารางนั้นเป็นหลัก ② ไม่มีตาราง แต่มี `.opencode/skills/` หรือ `.claude/skills/` → `ls` ดูแค่ชื่อ (กำกวมค่อย Grep `^description` ของ ≤3 ตัวที่ชื่อน่าจะตรง) ③ ไม่มีทั้งสองอย่าง = ข้ามเรื่อง skill ทั้งหมด · skill ส่วนกลาง (`~/.claude/skills`) ใส่ได้เฉพาะที่ตรงงานชัดเจน

## 1. สำรวจ + ยืนยัน (ห้ามเดา)
- **ต้นตอยังไม่ยืนยัน → ส่งผู้สืบ DeepSeek ก่อน** (ประหยัดโควตา Claude): ใช้ `/flash-investigate` หรือ `{{FLASHQ_RUN}} investigate "<บรีฟ 4 ช่อง>" --auto` (background · อ่านอย่างเดียว) · บั๊กกำกวม/เคยแก้แล้วไม่หาย → สืบ 2 session คนละโมเดล ต้องชี้ file:line ตรงกัน · **Claude เปิดเฉพาะ file:line ที่อ้าง 1–2 จุดเพื่อยืนยันก่อนเขียนแผนแก้** · บรรทัด `CITATIONS ... ผิด` = ข้อนั้นห้ามเชื่อ · ผู้สืบกับผู้แก้ต้องคนละ session
- ทุกจุดแก้ต้องมี: file:line จริง · โค้ด "ก่อน" ตรงตัว (copy จากไฟล์) · เหตุผล/หลักฐานว่าผิด · คำสั่งยืนยันที่รันได้
- ค้นหลายไฟล์/ไม่รู้ว่าอยู่ตรงไหน → **ส่งผู้สืบ Flash** (`flashq.py investigate ... --auto` ช่อง 4 = "คืนรายการ file:line + โค้ดที่คัดมา") แทน subagent ของ Claude (subagent กินโควตา Claude เท่ากัน) · subagent ใช้ได้เฉพาะเมื่อผู้สืบใช้ไม่ได้ (ไม่มี agent / โควตา Flash หมด) · ผลทุกทางต้องตรวจซ้ำเองที่ file:line
- **ผลสืบไม่พอ/กำกวม/CITATIONS ผิด = ส่งผู้สืบรอบใหม่ทันที** วนได้ไม่จำกัดจนพอ ไม่ต้องถาม user · **Claude ห้ามเปิดโค้ดเองเพื่อเติมบรีฟหรือไล่หาเอง** (เปิดได้เฉพาะยืนยันต้นตอหลัก ≤2 Read) · เช็กลิสต์ 6 ข้อตรวจรายงานผู้สืบ (file:line · โค้ด "ก่อน" ตรงตัว · เหตุผล/หลักฐาน · คำสั่งตรวจที่รันได้ · ค่าที่นับมาจริง · CITATIONS ไม่ผิด) และบันไดเมื่อวนเดิมไม่คืบ (บีบบรีฟแคบลง → เปลี่ยน `--model` → แบ่งบรีฟ → รายงาน user แบบ `ต้องทำเอง: … ลองแล้ว: … ขาด: … ขั้นที่ user ทำ: …`) อยู่ใน `/flash-investigate` §3.5
- ยืนยันไม่ได้หลังใช้บันไดจนหมด → ใส่เป็นงาน 🟡 พร้อมขั้น "พิสูจน์" หรือย้ายไป §5 นอกแผน — **ห้ามใส่งานเดาให้ Flash แก้** · 🟡 ไม่ใช่ทางเลี่ยงการสืบใหม่
- **คนเขียนแผนไม่ใช่คนทำงาน** (ถ้าทำเองหมด = เสียโควตา Claude แทน Flash · แผนช้าเป็นชั่วโมง):
  - **ห้ามทำต้นแบบเต็ม** (คัดลอกแอป/โมดูลไปแก้ทั้งชุดใน `.tmp/` แล้วเอา diff มาใส่แผน) · **ห้ามรันเกณฑ์/เทสต์ทั้งชุดเอง** — ผลตกของเกณฑ์ใช้จากท้าย output ของ `goal verify`/log ที่มีอยู่แล้ว
  - ลองได้แค่ **จุดเสี่ยงสั้น ๆ** ที่ไม่ลองแล้วเขียนแผนไม่ได้ (เช่น API ของ library มีจริงไหม · คำสั่ง Blender/Edge headless รันได้ไหม) · สูงสุด 3 ครั้ง · ครั้งละ ≤2 นาที · สคริปต์เล็กใน `.tmp/` · ผลที่ได้ใส่ในแผนเป็นหลักฐาน
  - **งบเวลาเขียนแผน ~20 นาที** (นับจากเริ่มสำรวจ) → ครบแล้วยังไม่ชัด = เขียนแผนจากที่ยืนยันแล้ว ส่วนที่เหลือเป็นงาน 🟡 "พิสูจน์ก่อนแก้" ให้ Flash ทำ หรือย้ายไป §5 · งานใหญ่เกินจะวางให้ครบใน 20 นาที = แบ่งเป็นหลายแผน/หลายรอบ (รอบแรกทำโครง + เกณฑ์ที่ง่ายก่อน)

## 2. ตัดงาน
- 1 งาน = 1 จุดแก้เล็ก (≤3 ไฟล์) + ยืนยัน + ข้อความ commit
- **"หลัง" ตรงตัว เฉพาะจุดแก้เล็ก** (โค้ดใหม่ ≤ ~20 บรรทัด) · โค้ดใหม่ยาว/ฟีเจอร์ใหม่/หน้าจอใหม่ = **สเปก** (จุดเสียบตรงตัว · ชื่อฟังก์ชัน/พารามิเตอร์/ผลลัพธ์ · พฤติกรรม · กรณีขอบ · เทสต์ที่ต้องผ่าน) แล้วให้ Flash เขียนโค้ดเอง — ดูแบบ T-02 ใน template (เทสต์ได้ → ใช้คู่กับ `แบบ: เทสต์ก่อน` แบบ T-03) · **ห้ามแปะโค้ดทั้งไฟล์/diff ยาว/ภาคผนวกโค้ด** (= Claude ทำงานเองผ่านแผน)
- **ขนาดแผน** (`flashq run` ตรวจเอง · ไม่มีทางลัด): ≤300 บรรทัด · โค้ดใน ``` รวม ≤100 · บล็อกเดียว ≤30 (เกิน = เตือนแต่ส่ง) · **>600 บรรทัด / โค้ดรวม >200 / บล็อกเดียว >60 / มีหัวข้อ "ภาคผนวก · คัดลอกตรงตัว · โค้ดเต็ม · appendix · verbatim" ที่มีโค้ด >20 บรรทัด = ปฏิเสธ** → แบ่งเป็นหลายแผน/หลายรอบ หรือเขียนเป็นสเปก · ข้อยกเว้นเดียว: ส่งเฉพาะรอบแก้ `T-xxR` ของแผนที่เคยรันแล้ว (เตือนแต่ผ่าน · ห้ามอาศัยข้อนี้โดยการเพิ่มโค้ดลงแผนเก่า)
- **ด่านแผนพิการ** (`flashq run` ตรวจงานที่สั่งเทียบ `<remote>/<main_branch>`): path ในหัวงาน/"ไฟล์:" ต้องมีจริง (ไฟล์ใหม่เขียน `(ใหม่)` ต่อท้าย หรือเขียนในบรรทัดที่บอกว่า "สร้าง…") · ข้อความ `ก่อน:` ต้องเจอ 1 ที่พอดี (ตั้งใจหลายที่ → เขียน "N ที่"/replace_all) = ผิดแล้ว**ปฏิเสธ** (`--skip-precheck` ข้าม) · คำสั่งใน ยืนยัน/แดง/เขียว ขึ้นต้นด้วย alias PowerShell (`sc` `r` `ls` `cat`…) / `function` ชื่อชน alias = เตือน
- งานที่ต้องออกแบบ/เลือกทาง/รอ user → §2 (ห้ามทำเอง) · **user ตอบแล้ว → เขียนเป็นงาน T-xx ในแผน (เพิ่มท้ายแผนเดิมถ้ายังไม่ส่ง หรือแผนรอบใหม่) แล้วส่ง Flash** — ห้ามลงมือทำเองเพราะ "user ตัดสินแล้ว เหลือแค่ทำ" · เรียงให้ build ผ่านได้ทุกงาน · DoD ต่อกลุ่ม
- เทสต์ใน DoD = เร็วแต่ครอบจุดที่แตะ · FAIL → rerun เฉพาะจุดนั้น 1 ครั้ง · ห้ามเริ่มทั้งชุดใหม่
- **งานแก้ลอจิกที่เทสต์ได้ → `แบบ: เทสต์ก่อน`** (ดู T-03 ในแม่แบบ · ไม่ใช้กับงานแก้ข้อความ/ค่าตั้ง/หน้าตา UI ล้วน หรือโปรเจกต์ที่ไม่มีตัวรันเทสต์) · คุณเขียนแค่ **สเปกเทสต์ + ข้อความ FAIL ที่คาด + คำสั่งรันเฉพาะเทสต์นั้น** — **ห้ามเขียนเทสต์ลงไฟล์จริงหรือรันเพื่อดูว่าล้มเอง** (Flash เป็นคนเขียน รันให้แดง แล้วจด log) · ข้อความ FAIL ที่คาดมาจากการอ่านโค้ดตรงจุดแก้ ไม่ใช่จากการลองรัน · ข้อยกเว้นเดียว = เทสต์เกณฑ์ใน `/flash-goal` ข้อ 1 ที่คุณเขียนเองอยู่แล้ว
- **บังคับ "หลักฐานชี้ขาด" ทุกงาน** = path log/ไฟล์ผลที่ DeepSeek สร้างตอนรันยืนยัน + บรรทัด/ค่าที่ต้องเห็น + ค่าก่อนแก้ (แยกได้ว่าแก้จริง) — `/flash-check` ตัดสินจากหลักฐานนี้อย่างเดียว ไม่รันซ้ำ · ออกแบบหลักฐานไม่ได้ = ยังไม่พร้อมส่ง

## 2.5 เลือกรุ่นผู้เขียนแผน (คุณภาพ + ประหยัด token ฝั่งผู้สั่ง)
- **งานใหญ่/เสี่ยง** = ≥4 งาน T-xx · ข้ามโมดูล · แตะ logic หลัก/ความปลอดภัย/protocol · ต้นตอยังไม่ยืนยันเต็มที่ → ต้องเขียนแผนด้วย **Opus**
  - session นี้เป็น Opus อยู่แล้ว → เขียนเองตาม §3
  - session ไม่ใช่ Opus (เช่น Sonnet) → **ส่ง subagent ด้วย Agent tool `model: "opus"`** (subagent_type `general-purpose`) ให้ทำ **เฉพาะข้อแรกของ §3 (เขียนไฟล์แผน)** · brief เป็นไทย ใส่: งาน + หลักฐานที่หาไว้แล้ว (file:line + โค้ด "ก่อน" ตรงตัว · อาการ · log · สิ่งที่ลองแล้ว · การตัดสินใจของ user · base commit) + path ไฟล์นี้ให้อ่าน §1–§3 · สั่งว่า **ห้ามแก้ซอร์สโค้ด ห้าม commit/push ห้ามทำ §4 · ห้ามทำต้นแบบเต็ม/รันเกณฑ์ทั้งชุดเอง (ลองได้แค่จุดเสี่ยงตาม §1) · งบเวลา ~20 นาที** · จุดที่ brief ให้ file:line มาแล้ว → Grep ยืนยันบรรทัดนั้น ไม่ต้องอ่านทั้งไฟล์ · Read ใช้ offset/limit · ขาดข้อมูล → หยุดแล้วบอกว่าขาดอะไร · ตอบสั้น: `PLAN=` · `TASKS=` · งานรอ user ตัดสิน · งาน 🟡 · หมายเหตุ
  - ได้ผลแล้ว agent หลักทำข้อที่เหลือของ §3 (ตรวจ `flashq-files:` ไม่เหลือ `<...>` · commit/push) และ §4 เอง (งานกลไก ราคาถูก)
- **งานเล็ก/กลไก** (≤3 งาน ในโมดูลเดียว ต้นตอยืนยันแล้ว หรือทำตามแผนที่มีอยู่) → เขียนเองด้วยรุ่นของ session นี้ ไม่ต้องเรียก Opus
- โปรเจกต์มี planner agent ของตัวเอง (เช่น `.claude/agents/*flash-planner*.md`) → ใช้ตัวนั้นแทน subagent ทั่วไป

## 3. เขียนแผน
- คัดลอก `{{FLASHQ}}/templates/FLASH_PLAN_TEMPLATE.md` → `<plan_dir>/PLAN_FLASH_<เรื่อง>.md` · เติม base commit (`git rev-parse --short HEAD`) + กติกาโปรเจกต์ใน §0
- **เติม `flashq-files:` ใน §0 ทุกครั้ง** = ทุกไฟล์ที่ทุกงาน T-xx จะแตะ (path จากรากโปรเจกต์ · คั่นด้วย `,` · glob ได้ เช่น `Client/Src/UI/*.cpp`) — คิวกลางโหมด auto ใช้ตัดสินว่ารันพร้อมงานอื่นได้ไหม (ไม่เติม = เดาจาก backtick · ดึงไม่ได้ = ต้องรอ) · แผนแตะไฟล์ที่ทุกโมดูลใช้ร่วม (เช่น CMakeLists.txt ระดับราก, Common/, Util/) หรือ build/สคริปต์ทั้งโปรเจกต์ → `flashq-parallel: no — <เหตุผลสั้น ๆ>` (**ต้องเขียนเหตุผลต่อท้ายทุกครั้ง** หน้าเว็บ/`status` แสดงให้ผู้ใช้เห็นตอนงานรอ) · ใช้ `flashq-parallel: no` ควรเขียน `flashq-exclusive: <path/glob>` ระบุขอบเขตเสมอ เพื่อไม่ให้บล็อกงานที่ไม่ชน · ห้ามเหลือ placeholder `<...>`
- **ใส่บรรทัด `skill: <ชื่อ>[, <ชื่อ>]` ในงาน T-xx ที่ตรง skill** (ใต้หัวงาน · ใส่เฉพาะ**ชื่อ**ตรงกับโฟลเดอร์ใน `skills/` · ห้ามคัดเนื้อหา skill ลงแผน · งานไม่ตรง skill ไหน = ไม่ต้องเขียนบรรทัดนี้) — `flash-worker` โหลดด้วย `skill` tool ก่อนลงมือ · `flashq run` เตือนถ้าชื่อไม่ตรง skill ที่มีจริง · **ไม่ผูกกับแม่แบบ**: แม่แบบแผนของโปรเจกต์ไม่มีช่องนี้ก็เขียนบรรทัดนี้เพิ่มได้เลย · โปรเจกต์ที่สั่งผู้วางแผนไม่โหลด skill (เช่น bughunt = หน้าที่ผู้สืบ/Flash) ไม่ขัดกัน — ผู้วางแผนแค่เขียนชื่อ ไม่ต้องโหลด
- commit เฉพาะไฟล์แผน + push เข้า `<remote>/<main_branch>` (อยู่ worktree/branch อื่น → merge แล้ว `git push <remote> HEAD:<main_branch>` · **ห้าม rebase**) — ทำตามกติกา commit ของโปรเจกต์ถ้ามี
- **ยืนยัน**: `git fetch <remote> <main_branch>; git merge-base --is-ancestor <hash แผน> <remote>/<main_branch>` ต้อง exit 0

## 4. ส่งเข้าคิวกลาง แล้วรอแจ้งผลจากระบบ (ไม่วน)
- รัน **ใน background** ที่โฟลเดอร์โปรเจกต์ (Bash/PowerShell `run_in_background: true` — **คำสั่งเดียวตรง ๆ เท่านั้น**: ห้ามต่อ `&` · `nohup` · `Start-Process` · `sleep` · `| head/tail` · ห้ามรันแบบ foreground — ยาม `run_guard.py` จะบล็อก):
  `{{FLASHQ_RUN}} run <path แผน> T-01..T-NN --switch-on-quota 4`
  (worktree → ใช้ checkout หลักเอง · ตรวจแผนใน remote + ขนาดแผน §2 · มีงานอื่นทั้งเครื่อง = รอคิว · โควตาหมด = สลับบัญชีแล้วสั่งซ้ำ) · ขึ้น `FLASH_RUN=FAIL แผนใหญ่เกิน` = แก้แผนตาม §2 แล้วส่งใหม่ (ห้ามหาทางเลี่ยง)
- บอก user สั้น ๆ: จำนวนงาน · งานที่รอ user ตัดสิน · "DeepSeek กำลังทำ — ดูใน opencode desktop session `flash <ชื่อแผน> <งาน>` · คิว `{{FLASHQ_RUN}}` · จบแล้วผมตรวจต่อแล้วแจ้ง"
- **ติดคิว (`QUEUED`) = ปกติ ไม่ต้องส่งซ้ำ** — process เดิมรอคิวแล้วเริ่มเอง และคำสั่ง background นี้จบเมื่องานจบ · ถ้าเผลอส่งผิดวิธีไปแล้ว: `{{FLASHQ_RUN}} wait <job>` ด้วย `run_in_background: true` เพื่อให้มีตัวเฝ้า
- **แล้ว หยุดนิ่งรอแจ้งเตือนจากระบบ** (คำสั่ง background จบ = ระบบแจ้งเข้า session นี้เอง · ไม่เสียอะไรระหว่างรอ) · **ห้าม** sleep / poll / `flashq status` วน / เปิดงานเรื่องอื่นต่อ
- **ได้แจ้งว่าจบ (ทุกสถานะ: OK · OK_UNVERIFIED · FAIL · DENIED · QUOTA · TIMEOUT · NOSTART · BUSY) → เรียก `/flash-check <path แผน>` ทันที** พร้อมบรรทัด `FLASH_RUN=...` (ไม่ OK = `/flash-check` §0 วินิจฉัยและแจ้ง user — ห้ามเงียบ · OK_UNVERIFIED = จบแต่ยังไม่มีหลักฐาน อ่านบรรทัด `WARN:` แล้ว `/flash-check` ตามปกติ) · session เป็น Opus/Fable → `/flash-check` ส่ง subagent `flash-checker` ตรวจแทน (ถูกกว่าตรวจเอง)
- **ถ้า session นี้ปิดไปก่อน / user พิมพ์ข้อความมาก่อนงานจบ**: `flashq` เขียนผลลง `~/.flashq/inbox/` + toast Windows ให้เอง · hook `inbox_notify.py` (ลงด้วย `install --hooks`) แทรกผลตอน user พิมพ์ข้อความถัดไป (ทุก session ในโปรเจกต์นี้) → เห็นแล้ว `/flash-check <path แผน>` ต่อ · ไม่มีใครรอแล้วงานจบเงียบ ๆ ไม่ได้
- สำรอง: ให้บรรทัด `/flash <path แผน> T-01..T-NN` ไปวางใน opencode (เปิดที่ checkout หลัก) แล้วตรวจด้วย `/flash-check <path แผน>`
