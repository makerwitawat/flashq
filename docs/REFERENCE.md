# flashq — คู่มืออ้างอิงฉบับเต็ม

> ภาพรวมและการเริ่มต้นใช้งาน → [README.md](../README.md) · หน้านี้รวมรายละเอียดทุกคำสั่ง ทุกค่าตั้ง และพฤติกรรมของตัวจัดคิว

Claude Code วางแผน → `flashq run` ส่งงานเข้าคิว → opencode `/flash` ให้ `flash-worker` ลงมือ → Claude ตรวจผล

## ทำไมต้องมีคิวกลาง
- ทุกโปรเจกต์ใช้บัญชีโมเดลชุดเดียวกัน → ถ้ารันซ้อนกันจะชนโควตา · ค่าเริ่มต้นคิวนี้ทำ **ทีละงานทั้งเครื่อง** ตามลำดับที่ส่ง (FIFO)
- **รันคู่ขนาน**: `python flashq.py config max_parallel 2` (1-8 · หรือเลือก "พร้อมกัน" ในหน้าเว็บ) → มีหลายช่องรัน หัวคิวได้ช่องก่อนเสมอ · `runnow <id>` = ให้งานที่รอคิวได้ **ช่องพิเศษครั้งเดียว** แม้เกินค่า (ตรวจไฟล์ที่แผนจะแตะซ้อนกับงานที่กำลังทำก่อน · ซ้อน = ต้องใส่ `--force` · งานที่ได้ช่องเพราะข้ามตัวจัดคิวจะมีธง `forced` ใน job และ `status` แสดง "ผู้ใช้สั่งรันเลยข้ามคิว")
- **จัดคิวอัตโนมัติ** `python flashq.py config schedule auto` (หรือเลือก "จัดคิว: อัตโนมัติ" ในหน้าเว็บ · ตั้ง max_parallel เป็น 2 ให้ถ้ายังเป็น 1) → ทุกครั้งที่มีช่องว่าง ไล่คิวตามลำดับแล้วเริ่ม **งานแรกที่ไม่ชน** กับงานที่กำลังทำ (ข้ามงานที่ชนได้) · ไม่มีไฟล์ config = `fifo` ทีละงานแบบเดิม
  - **ชน** (อนุรักษ์ · ไม่แน่ใจ = ชน): โปรเจกต์ต่างกัน = ไม่ชน · โปรเจกต์เดียวกัน → ไฟล์ที่แผนจะแตะซ้อนกัน (glob/โฟลเดอร์ครอบ) · ดึงรายการไฟล์ไม่ได้ (เช่น `--message`) · แตะไฟล์ที่ทุกโมดูลใช้ร่วม **เมื่อทั้งสองงานแตะ** (ไฟล์ระดับรากที่มีจริง เช่น `CMakeLists.txt` · โฟลเดอร์ `Common/` `Util/` `Shared/` `cmake/` · เพิ่มเองด้วย `"parallel_shared": ["Proto/"]` ใน `.flash.json`) — ฝั่งเดียวแตะไม่ชน · อยากกลับไปโหมดเดิม (ฝั่งเดียวแตะก็ชน) ตั้ง `"parallel_shared_strict": true` ใน `.flash.json` · แผนประกาศ `flashq-parallel: no` = บล็อกทั้งโปรเจกต์ เว้นแต่ประกาศ `flashq-exclusive: Build/*, CMakeLists.txt` = ห้ามเฉพาะไฟล์ในขอบเขตนั้น (อีกงานไม่แตะขอบเขต = รันพร้อมกันได้ · ไม่ใส่ `flashq-exclusive` = บล็อกทั้งโปรเจกต์เหมือนเดิม)
  - แผนประกาศชุดไฟล์เองใน §0: `flashq-files: Client/Src/A.cpp, Client/Src/UI/*.h` (ใช้แทนการเดาจาก backtick · แม่แบบมีให้แล้ว)
  - **กันอดตาย**: งานที่ชนแล้วรอเกิน `starve_min` นาที (ค่าเริ่มต้น 120 · `config starve_min 60`) = ล็อกเป็นหัวคิว — งานหลังจากนั้น**ที่ชนกับมัน**ห้ามแซง (งานที่ไม่ชนแซงได้)
  - **ป้ายงานที่ process ตาย** (แผง "⚠ ต้องรับทราบ" / ป้ายเก้าอี้ในออฟฟิศ): ไม่หายเองจนกว่าจะกด "รับทราบ" (รายงาน) หรือ "รับทราบทั้งหมด" (มี ≥2 งาน · `POST /api/dismiss {all:true}` · ข้ามงานที่ opencode ลูกยังทำงานอยู่) · หรือหายเองเมื่อไฟล์งานไม่ถูกเขียนเกิน `dead_clear_hours` ชั่วโมง (ค่าเริ่มต้น 24 · `config dead_clear_hours 48` · 0 = ไม่หายเอง) — ทุกทางบันทึกเป็นสถานะ `dead` ย้ายไปประวัติ
  - `status` / หน้าเว็บบอกเหตุผลที่แต่ละงานยังไม่เริ่ม ("รอช่องว่าง" · "ชนกับ <job>: ไฟล์ X" · "แผนสั่งให้รอ" · "กันอดตาย") · ปุ่มรันเลยยังใช้บังคับเริ่มได้
- ระหว่างรันหลายงาน `--switch-on-quota` จะ **ไม่สลับบัญชีซ้ำ** ถ้างานอื่นเพิ่งสลับไปแล้ว (ใช้บัญชีใหม่นั้นสั่งซ้ำแทน)
- ของเดิม (ล็อกรายโปรเจกต์) เจองานซ้อนแล้วตอบ `BUSY` ทิ้ง · ตัวนี้ **รอคิวให้เอง** (`--no-wait` = พฤติกรรมเดิม)

## บทบาท
- **Claude = เจ้าของงาน**: สืบข้อเท็จจริง · เขียนแผน/บรีฟให้ชัดถึง file:line · สั่งงาน · ตรวจผลเอง และเป็นคนตัดสินสุดท้าย
- **OpenCode (Flash) = ผู้ผลิต/ผู้ตรวจ/ผู้สืบ/นักทดสอบ/ช่างเอกสาร** เพราะโควต้าเยอะกว่า: `flash-worker` ทำตามแผน · `flash-verifier` หาข้อผิดอิสระ · `flash-investigator` ไล่หาต้นตอ (อ่านอย่างเดียว) · `flash-tester` อธิบายสาเหตุที่ชุดทดสอบล้ม (อ่านอย่างเดียว) · `flash-writer` อัปเดตเอกสารให้ตรงโค้ด (แก้ได้เฉพาะ path ที่ชุดอนุญาต)
- ผลของผู้ตรวจ/ผู้สืบเป็นข้อมูลประกอบ ไม่ใช่คำตัดสิน — Claude ต้องเปิดดูโค้ดเองอย่างน้อยจุดหลัก
- งาน verify/investigate: timeout ค่าเริ่มต้น `agent_timeout_min` = 30 นาที · ถ้าไฟล์ในโปรเจกต์เปลี่ยนระหว่างรัน (git status) จะขึ้น `WARN` ห้ามเชื่อผลจนกว่าจะตรวจ `git diff`
- **ระดับความคิด** (`variants` · ส่งเป็น `opencode --variant`): ค่าเริ่มต้น ผู้สืบ `high` · ผู้ตรวจ `low` · นักทดสอบตอนอธิบายสาเหตุ `high` · งานทำ ไม่ส่ง (provider ใช้ค่าของมันเอง) · ทับได้รายชนิดงาน (`work`/`verify`/`investigate`/`qa`/`doc`) ใน `.flash.json` หรือ `~\.flashq\config.json` เช่น `{"variants": {"verify": "high", "work": "low"}}` · ลำดับ: `--variant` ใน CLI > `.flash.json` > `config.json` > ค่าเริ่มต้น · `""` หรือ `"none"` = ปิดของชั้นล่าง · ค่าที่ใช้ได้ขึ้นกับโมเดล/provider (opencode-go: low/high/max · commandcode2: low/medium/high/max) · บันทึกลงงานเป็น `variant` และขึ้น `variant=…` ในบรรทัด START · หน้าเว็บบอกทุกตัวละครที่ใช้โมเดล (ผู้ทำ/ผู้ตรวจ/ผู้สืบ/นักทดสอบ/ช่างเอกสาร): ฉากออฟฟิศ (ป้าย 🧠 ใต้โต๊ะ + บรรทัดในแถบ + การ์ด/คิว/เพิ่งจบ) และแดชบอร์ด (การ์ดงานที่กำลังทำ · คิว · ประวัติ) · `/api/state` มี `variant` ทุกแถว (งานรอคิว = ค่าที่จะส่ง · ว่าง = ไม่ส่ง แสดงเป็น "ปกติ") · ยามไม่ใช้โมเดลจึงไม่มีป้าย
- **งานค้าง**: log เงียบเกินเกณฑ์ = max(`stall_floor_min` 8 นาที, 6 × ช่วงเงียบที่นานสุดที่เห็นในงานนี้) แต่ไม่เกินเพดาน `stall_min` 20 นาที (ผู้ตรวจ/ผู้สืบ: `agent_stall_floor_min` 4 / `agent_stall_min` 10) · งานที่ปกติขยับทุกครึ่งนาทีจึงถูกตัดที่ ~8 นาที ไม่ต้องรอ 20 · **รอโมเดลอย่างเดียว** (`model_wait_min` 4 · ต้อง `--attach live` ให้ถาม server ได้): server ยืนยันว่าไม่มี tool ใดรันอยู่และไม่มีอะไรขยับเกินนี้ = ตัดทันที ไม่รอขั้นต่ำ 8 นาที · เงียบถึงครึ่งเกณฑ์จะพิมพ์ `WARN: ไม่มีความเคลื่อนไหว …` เตือนล่วงหน้า · รอบลองใหม่หลัง STALL ย้ายไปผู้ให้บริการอื่นของโมเดลเดิม (ถ้ามี · งานทำจริงที่ไม่ได้ระบุ `--model` ก็ย้าย) หรือเกินเวลารวม → flashq ฆ่า แล้วรายงาน `FLASH_RUN=TIMEOUT` + `REASON` + `DIAG` (tool ล่าสุดก่อนถูกฆ่า) · ถ้าเหตุคือ log เงียบ (มักเป็น request ไปโมเดลไม่ตอบ) flashq ลองใหม่เองหนึ่งครั้ง (`/flash` ข้ามงานที่ติ๊ก `[x]` แล้ว) · ถ้าซ้ำ/เกินเวลารวม ให้ Claude ดู DIAG + `git status` แล้วแบ่งงานให้เล็กลงก่อนสั่งใหม่ · ตั้ง 0 = ปิดการเฝ้า
- **ตัวเฝ้า shell** (`shell_idle_min` 4 · 0 = ปิด · Windows + `--attach` server): opencode รันคำสั่งแล้วรอเฉย ๆ ไม่รู้ว่าโปรเซสตายหรือยังทำงาน · เมื่อ log เงียบเกิน 30 วิ flashq ถาม server ว่า bash ตัวไหนกำลังรัน แล้วหาโปรเซสของคำสั่งนั้น (shell + ลูกหลาน) วัด CPU+I/O ทุก 30 วิ · ขยับ = ปล่อยไป (กันเกณฑ์งานค้างไม่ให้ฆ่างาน build ยาวที่ยังทำงานจริง) · นิ่งสนิทเกิน `shell_idle_min` หรือ shell จบแล้วแต่ลูกกำพร้า (`start /b`, `&`, server) ยังถือ handle ไว้ → **ฆ่าเฉพาะคำสั่งนั้น** tool คืน error แล้วโมเดลทำต่อ (ไม่ฆ่าทั้งงาน) · พิมพ์ `SHELL_WATCH:` + บันทึก `shell_kills` ในงาน · หน้าออฟฟิศมี 🛡 ยามเฝ้า shell (ชุดกรมท่า ถือไฟฉาย) แถบล่างสุด + บรรทัด 🛡 บนการ์ดงาน
- **ตรวจสด ๆ: `flashq why [id]`** (ไม่ระบุ id = ทุกงานที่รัน · ปุ่ม `🔍 ตรวจสาเหตุ` บนการ์ดงานในหน้าออฟฟิศ) — บอก log เงียบกี่นาที · subagent/tool ขยับล่าสุดเมื่อไร · tool ไหนรันอยู่มานานเท่าไร แล้วสรุป: ปกติ / tool นานแต่อาจยาวจริง / **tool ค้าง** (ถ้าคำสั่งเปิดโปรเซสเบื้องหลังจะเตือนว่า tool รอ handle ไม่คืน) / **รอโมเดล** / แยกไม่ได้ (`--attach none`) · ความคืบหน้า "เสร็จ N/M งาน" ในหน้า UI นับจากกล่อง `[x]` ในแผนจริง
- **ค้างที่ shell/tool หรือที่โมเดล?** เมื่อ `--attach live` flashq ถามเซิร์ฟเวอร์ opencode ว่า session + subagent ลูกขยับล่าสุดเมื่อไรและมี tool ไหนรันอยู่ → (ส่ง `directory` ของโปรเจกต์ไปด้วย · ไล่ subagent ซ้อนได้ · ถามสดทุกครั้งก่อนตัดสินฆ่า) → (1) log ของ parent เงียบแต่ subagent ยังทำอยู่ = **ไม่ฆ่า** (2) ค้างจริง = ฆ่า + สั่ง server `abort` session นั้นด้วย (ไม่งั้น session บน server ยังเดินต่อ แก้ไฟล์ซ้อนกับรอบลองใหม่) แล้วบอก `สาเหตุ: tool bash ค้าง (<คำสั่ง>) รันมา N นาที` หรือ `ไม่มี tool รัน → รอโมเดล/ผู้ให้บริการตอบไม่ได้` (3) `--attach none` ถามไม่ได้ → บอกว่าแยกสาเหตุไม่ได้ · worker ถูกสั่งให้ตั้ง timeout ให้คำสั่ง shell เองด้วย
- **`RULE_DENIED:`** = agent พยายามรันคำสั่ง shell ที่กฎของ agent ไม่อนุญาต (เช่น find/python) — ไม่ใช่งานล้มเหลว · agent อ่านอย่างเดียวอนุญาต git show/diff/log/grep/status/ls-files/blame · ls cat head tail wc grep (ห้าม `>`) · ต่างจากสถานะ `DENIED` (opencode ปฏิเสธสิทธิ์เอง งานไม่ได้ทำ — ดูหัวข้อ "งานถูกปฏิเสธสิทธิ์")
- `CITATIONS:` ของผู้สืบมี 5 ช่อง: "ตรงถึงโค้ด" (คัดข้อความอยู่ในบรรทัดจริง) · "ตรงแค่ไฟล์/บรรทัด" (ไฟล์/บรรทัดมีจริงแต่ไม่ได้คัดโค้ด) · **ผิด** (ข้อความที่คัดไม่อยู่ในบรรทัดนั้นและห่างเกิน 40 บรรทัด หรือไฟล์/บรรทัดไม่มีจริง — ลดผลเป็น `OK_UNVERIFIED`) · **ตรวจไม่ได้** (ชื่อกำกวม/path ย่อ/ไม่ใช่ไฟล์ — ไม่ลดผล เว้นแต่เกินครึ่งและไม่มีข้อที่ตรงถึงโค้ด) · **เลขเพี้ยน** (ข้อความอยู่ห่าง ≤40 บรรทัด บอกเลขบรรทัดที่ถูก — ไม่ลดผล) — พิสูจน์ได้แค่ว่าโค้ดที่อ้างมีจริง ไม่ใช่ว่าเป็นต้นตอจริง
  - ชื่อไฟล์ย่อ (`viewer.py` = `rig_std_viewer.py`) ใช้ได้เมื่อชี้ไฟล์เดียว · ชื่อซ้ำหลายที่ → เลือกอันที่อยู่โฟลเดอร์เดียวกับ citation อื่นที่ระบุ path ครบ ไม่ได้ก็ขึ้น "กำกวม" (ไม่เดา) · ข้อความที่คัดติด citation (≤40 ตัวอักษร ก่อน ` · ` / ` → ` / `:123`) เทียบกับบรรทัด ±3 · ที่ห่างกว่านั้นถ้าหน้าตาเป็นโค้ด/path เทียบทั้งไฟล์ (ไม่มีในไฟล์เลย = ผิด) · ช่วง `a.py:48-53` นับถึงบรรทัดท้าย · `...` ย่อกลางข้อความได้ · "ไม่มีคีย์ `x`" ไม่ตรวจ · host:port (`127.0.0.1:8219`) ไม่นับเป็น citation
- ข้อจำกัดที่ยังทดสอบกับของจริงไม่ได้: โควต้าหมดจริงของผู้ให้บริการ (ทดสอบได้เฉพาะ opencode ปลอม) · ผู้ตรวจทดสอบจริงแล้วกับ commit ที่ใส่ความผิดไว้ 3 จุด (สูตรผิด/ไฟล์นอกแผน/log ปลอม) จับได้ครบ แต่ยังเป็นตัวอย่างเดียว

## ติดตั้งครั้งแรก
```
python D:\MyCode\flashq\flashq.py install
```
ใช้ชุดแจก exe (ไม่ต้องมี Python) → `flashq.exe install` จากโฟลเดอร์ชุดแจก: ไฟล์ที่ติดตั้งจะเรียก `flashq.exe` ตัวนั้นแทน `python flashq.py` · `--hooks` เป็นสคริปต์ `.py` ที่ `settings.json` สั่ง `python <hook>.py` จึงต้องมี Python 3 — ไม่มี = `install --hooks` ข้ามให้พร้อมบอกเหตุผล (คำสั่ง `/flash-*` ใช้ได้ตามปกติ) · คู่มือ → [INSTALL_EXE.md](INSTALL_EXE.md)

แล้วรีโหลด opencode desktop · ไฟล์ที่ flashq ติดตั้งไว้เอง (`flashq:managed`) ทับได้เลยไม่สำรอง (ต้นฉบับอยู่ใน git ของ repo นี้) · ไฟล์ที่มีอยู่แล้วแต่ไม่ได้มาจาก flashq จะถูกข้าม (`--force` = สำรอง `.bak-flashq-*` แล้วทับ) · `--hooks` = ลงทะเบียน `image_guard.py` เป็น PreToolUse(Read) และ `inbox_notify.py` เป็น UserPromptSubmit ใน `~/.claude/settings.json` (ทำซ้ำได้ · ปิดชั่วคราว 60 นาที = สร้างไฟล์ `~/.flashq/image_guard_off` · เพดานตั้งใน `~/.flashq/config.json`: `image_max_px` `image_max_reads`)

### เลือกโมเดลบนเครื่องใหม่ (`flashq models`)
`install` ท้ายงานตรวจว่าทุกบทบาท (ผู้ทำ `flash-worker` · ผู้ตรวจ `flash-verifier` · ผู้สืบ `flash-investigator` · นักทดสอบ `flash-tester` · ช่างเอกสาร `flash-writer`) มีโมเดลที่ใช้ได้บนเครื่องนี้ — ขาด/ไม่มีในเครื่อง = ถามเลือกเมื่ออยู่ใน terminal (ไม่มี TTY เช่นรันจาก Claude Code = แค่บอกวิธีแก้ ไม่ค้างถาม) · `install --models auto` ตั้งตัวแนะนำให้ · `--models skip` ไม่ตรวจ
```
python flashq.py models                      # แสดงโมเดลทั้งหมดที่เครื่องนี้มี แล้วถามว่าจะใช้แบบไหน
python flashq.py models --list               # ดูรายการ + สถานะแต่ละบทบาท ไม่เปลี่ยนอะไร
python flashq.py models --auto               # บทบาทที่ยังไม่ตั้ง/ใช้ไม่ได้ → ตั้งเป็นตัวแนะนำ (ที่ใช้ได้อยู่แล้วไม่แตะ)
python flashq.py models --set worker=provider/model --set verifier=provider/model
python flashq.py models --all provider/model # โมเดลเดียวทุกบทบาท
```
- รายการ = `opencode models` + โมเดลที่ประกาศใน `opencode.json` (`provider.<p>.models`) จัดกลุ่มตาม provider · ติดป้าย **(แนะนำ)** ที่ชื่อท้ายตรงกับรายการแรกของ `accounts.json` (`deepseek-v4.1-flash`) และ **← ใช้อยู่** ที่บทบาทใช้
- ตอนถาม: เมนู 1 ตัวแนะนำทุกบทบาท · 2 โมเดลเดียวทุกบทบาท · 3 เลือกแยกรายบทบาท · 0 ไม่เปลี่ยน · เลือกโมเดลด้วยเลขที่ / ชื่อเต็ม / พิมพ์ส่วนของชื่อเพื่อกรอง (เลขอ้างรายการเต็มเสมอ) / `*` ดูทั้งหมด / Enter = ค่าในวงเล็บ / `0` ข้าม
- เขียนที่ `agent.<ชื่อ>.model` ใน `opencode.json` (สำรองครั้งแรกเป็น `opencode.json.bak-flash-models` · ไฟล์ JSON เสียจะไม่เขียนทับ) และแก้บรรทัด `model:` ในหัวไฟล์ agent ที่ flashq ติดตั้ง · `install` รอบหลังไม่ทับโมเดลที่เลือกไว้กลับเป็นค่าในต้นฉบับ · ชื่อที่ไม่มีในเครื่อง = ปฏิเสธทั้งชุดไม่เขียนครึ่งเดียว
- ลำดับสลับบัญชีตอนโควตาหมด: `accounts.json` ใน repo ใช้ชื่อ provider ของเครื่องหลัก → ถ้ามีรายการที่เครื่องนี้ไม่มี `models` (ตอนตั้งค่า/`--auto`/ถาม) สร้าง `~/.flashq/accounts.json` ของเครื่องนี้ให้ = โมเดลที่ชื่อท้ายเดียวกับผู้ทำ เรียงผู้ทำก่อน · ไฟล์นี้มาก่อนของ repo เสมอ (`flashq switch` · สลับตอนโควตาหมด · หน้าเว็บใช้ตามนี้) · ลบไฟล์ = กลับไปใช้ของ repo · `--list` / ไม่ใส่ flag ในที่ไม่มี TTY ไม่เขียนอะไร แค่เตือน

## ประหยัด token ของ Claude (เหตุผลที่เครื่องมือนี้มีอยู่)
- **แผน = สเปก ไม่ใช่โค้ดสำเร็จรูป**: `flashq run` ตรวจขนาดแผนเอง — เตือนเมื่อ >300 บรรทัด / โค้ดใน ``` รวม >100 / บล็อกเดียว >30 · **ปฏิเสธ** เมื่อ >600 / >200 / >60 หรือมีหัวข้อ "ภาคผนวก · คัดลอกตรงตัว · โค้ดเต็ม · appendix · verbatim" ที่มีโค้ด >20 บรรทัด (ไม่มีตัวเลือกเลี่ยง · ยกเว้นส่งเฉพาะรอบแก้ `T-xxR` ของแผนที่เคยรันแล้ว = เตือนผ่าน) — แผนที่ Claude เขียนโค้ดเต็มให้ Flash คัดลอก = Claude ทำงานเองในราคาแพงกว่า
- **วางแผน → ส่ง → รู้ผล → ตรวจ → แจ้ง ใน flow เดียว (คืนแล้ว 2026-10-22)**: `/flash-plan` ส่งเข้าคิวด้วย `flashq run` ใน background แล้ว**หยุดนิ่งรอ** — จบแล้วระบบแจ้งเข้า session เดิมเอง (ห้าม sleep/poll วน = ไม่เสีย token ระหว่างรอ) → `/flash-check` ทันทีทุกสถานะ · session Opus/Fable → subagent `flash-checker` ตรวจแทน · ปิด session ไปก่อน → inbox + toast + hook (ด้านล่าง) · เปิด session Sonnet ใหม่รัน `flashq wait <แผน>` ก็ยังทำได้ถ้าอยากแยก · ตั้งค่า `"model": "claude-sonnet-5"` ใน `.claude/settings.json` ของโปรเจกต์ให้ session ใหม่เริ่มที่ Sonnet
- **รูปภาพ**: รูป 1 รูป ≈ 1–1.6k token แต่**ค้างใน context ทุก turn** จนจบ session → `flashq shrink <รูป>` ย่อเป็น `.tmp/shrink/<ชื่อ>.jpg` (ด้านยาว 800px) ก่อนอ่าน · hook `image_guard` บล็อกรูปใหญ่/อ่านรัวให้เอง
- `python flashq.py wait <job|แผน> [--timeout-min 480]` = บล็อกจนงานจบแล้วพิมพ์ `FLASH_RUN=...` (exit 0 = OK · 1 = ไม่ OK · 3 = ยังไม่จบ) · OK_UNVERIFIED นับเป็น exit 0 แต่มีบรรทัด WARN บอกเหตุ (`run` · `wait` · `log` พิมพ์บรรทัด `WARN: ผล OK ยังไม่ยืนยัน — …`) — Claude รันใน background แล้วรอแจ้งเตือน ไม่ต้องวนถาม `status`
- **แจ้งผลงานจบกลับมาเอง (ไม่เสีย token ระหว่างรอ)**: งานจบทุกสถานะ (OK · FAIL · DENIED · QUOTA · TIMEOUT · NOSTART · BUSY · QUEUE_TIMEOUT) → `flashq` เขียนผลลง `~/.flashq/inbox/` + toast Windows (ไม่เรียกโมเดล) · hook `inbox_notify.py` (`UserPromptSubmit` · ลงด้วย `install --hooks`) แทรกผลให้ Claude เห็นตอนผู้ใช้พิมพ์ข้อความถัดไป พร้อมคำแนะนำ (OK → `/flash-check <แผน>` · ไม่ OK → ดูสาเหตุด้วย `flashq log <job>`) · ส่งถึง session ที่สั่ง (`CLAUDE_CODE_SESSION_ID`) หรือ session อื่นในโปรเจกต์เดียวกันเมื่อค้างเกิน 30 นาที · ส่งแล้วย้ายไป `inbox/done/` · ปิด: `config.json` `{"notify": false}` (เฉพาะ toast: `"notify_toast": false`) · งานที่ process ตายกลางทาง (DEAD) hook เรียก `flashq sweep` ตรวจแล้วแจ้งให้ครั้งเดียวต่องาน · ข้อจำกัดที่เหลือ: Claude เห็นผลเมื่อผู้ใช้พิมพ์ข้อความ ไม่ใช่เด้งเข้า session ที่ปิดอยู่เอง → ใช้ปุ่ม **"เปิด Claude ตรวจ"** บนการ์ดงานในหน้าเว็บ (เปิด session ใหม่พิมพ์ `/flash-check` รอไว้ กด Enter เอง · ไม่เปิดเองอัตโนมัติ กันกิน token โดยไม่รู้ตัว)
- **วัดว่าแต่ละแผนกิน token Claude เท่าไร**: `python flashq.py usage <แผน|โฟลเดอร์โปรเจกต์> [--since 30]` สแกน transcript ของ Claude Code (`~/.claude/projects/` เฉพาะโฟลเดอร์ที่ cwd ตรงกับโปรเจกต์ รวม worktree · อ่านทีละบรรทัด ไม่โหลดทั้งไฟล์) เอา session ที่อ้างถึงชื่อแผนหรือเรียก `/flash-plan` `/flash-check` `/flash-goal` มารวม token แยกขั้น (วางแผน · ตรวจ · รอบแก้ `T-xxR`) และโมเดล + ประเมิน USD โดยประมาณ (ตารางราคาในตัว · ทับได้ที่ `~/.flashq/config.json` ช่อง `"prices": {"claude-opus-5-5": {"in": 4, "out": 20, "cache_read": 0.2, "cache_write": 5}}` USD/MTok · หรือรูปย่อ `[in, out, cache_read, cache_write]`) · บรรทัดสรุป `USAGE=<แผน> claude_in=… claude_out=… cache_read=… sessions=…` (exit 1 = ไม่พบ session) · ผลล่าสุดเก็บที่ `~/.flashq/usage/<แผน>.json` ให้หน้าเว็บโชว์บรรทัด "🪙 Claude ใช้ ~Nk token (~$x) · วางแผน a% · ตรวจ b%" บนการ์ดงาน/การ์ดธง · ให้โฟลเดอร์โปรเจกต์แทนแผน = ทุกแผนที่ถูกพูดถึงในช่วงนั้น
- **ดู token ที่ Flash ใช้ + ประหยัดไปเท่าไร**: `python flashq.py usage --flash [โฟลเดอร์โปรเจกต์] [--since 30]` หรือการ์ด "🪙 token ของ Flash · ประหยัด" บนหน้าเว็บ (เลือก 7/30/90 วัน · หน้า office มีช่องสรุปยอดประหยัดด้วย) — รวมจาก log ของงานที่รันผ่าน flashq + subagent ใน `opencode.db` (token ของ opencode ที่ใช้นอก flashq ไม่นับ) · ตัวเลขประหยัดเป็น**ค่าประมาณ**: สมมติ Claude ใช้ token เท่ากัน (จริงมักน้อยกว่า) แล้วหักค่า Claude ที่วัดได้จาก `flashq usage <แผน>` — ยิ่งรัน `usage <แผน>` ครบ ตัวเลขยิ่งใกล้จริง · เปลี่ยนรุ่นที่ใช้เทียบ: `config.json` → `"flash_compare": ["claude-sonnet-5-5", "claude-opus-5-5"]`

## โปรเจกต์ใหม่ (ครั้งเดียวต่อโปรเจกต์)
```
cd <โฟลเดอร์โปรเจกต์>
python D:\MyCode\flashq\flashq.py init --install --commit       # ครบในคำสั่งเดียว
```
**ง่ายสุด:** พิมพ์ `/flash-init` ใน Claude Code ที่โปรเจกต์นั้น (หรือสั่ง `/flash-plan` ได้เลย — ถ้าไม่มี `.flash.json` จะรัน init ให้เอง) · ตัวเลือก: `--install` ติดตั้งคำสั่ง global ที่ขาด · `--commit` commit เฉพาะไฟล์ที่ init แตะ (ไม่แตะไฟล์อื่นที่ค้าง) + push ถ้าอยู่ branch หลัก · `--force` ทับด้วยค่าที่ตรวจเจอ
- ตรวจ `remote` + branch หลัก (`main`/`master`/อื่น) จาก git เอง แล้วเขียน `.flash.json` · เพิ่ม `.tmp/` ใน `.gitignore` · คัดลอกแม่แบบแผนไป `docs/plans/` (แทน `{{FLASHQ_RUN}}` ในแม่แบบเป็นคำสั่งรัน flashq ของเครื่องนั้น: `python <repo>/flashq.py` หรือ path ของ `flashq.exe`) · เช็ก `opencode` + คำสั่ง global (`--install` = ติดตั้งที่ขาดให้) · ไม่มี remote = ตั้ง `require_plan_in_remote: false`
- ไม่ทับค่าที่ตั้งไว้ใน `.flash.json` (`--force` = ทับด้วยค่าที่ตรวจเจอ) · รันซ้ำได้ · **ไม่ commit/push ให้** — ท้ายผลลัพธ์บอกขั้นถัดไป
- ไม่รัน `init` ก็ได้: ถ้า `.flash.json` ไม่ได้ตั้ง `main_branch`/`remote` ตอน `run` จะตรวจจาก git เอง (remote HEAD → `origin/main`/`origin/master` ที่มีจริง) · ตั้งเองใน `.flash.json` ชนะเสมอ

### โหมดเป้าหมาย `/flash-goal` — ตั้งธงแล้ววนจนผ่าน

- **ธงอัปเดตเมื่อไร**: เกณฑ์ ✅/❌ และ "ตรวจแล้ว n/max รอบ" เปลี่ยนเฉพาะตอน `goal verify` (Flash ทำเสร็จเฉย ๆ ยังไม่นับ) · ระหว่างนั้นการ์ดบอกขั้น/รอบที่กำลังทำจากงานที่รันหรือรอคิว (ชื่อแผน `_R<n>`) และขึ้น ⚠ "รอบ X Flash ทำเสร็จแล้วแต่ยังไม่ได้ goal verify" เมื่อมีรอบค้างตรวจ · การ์ดยังแสดงสถานะ session เจ้าของธง (จาก transcript ของ Claude Code)
- **ทางออกเมื่อ STOP** (`goal status`/`verify` พิมพ์บรรทัด `ทางออก:`): ไฟล์นอกขอบเขต/ไฟล์ล็อก → `flashq goal ack <GOAL> --reason "<เหตุ user>"` (ไม่ล้าง base/รอบ · ตรวจเฉพาะที่แก้หลัง ack) · ครบงบรอบ/เวลา → `flashq goal check <GOAL> --extend N --extend-hours H` · เริ่มใหม่ทั้งหมด → `goal check --reset` · สถานะสำรองที่ `~/.flashq/goal-state/` (ต้นฉบับ `.tmp/flashq-goal/` หาย = กู้ให้เอง)

### งานทดสอบ (qa) — นักทดสอบรันชุดทดสอบของโปรเจกต์
```
python D:\MyCode\flashq\flashq.py qa [ชุด...] [--commit <sha>] [--project P] [--no-analyze] [--fail-fast] [--retry N] [--cmd "<คำสั่ง>"] [--auto]
```
- **flashq รันคำสั่งทดสอบเอง** แล้วตัดสินจาก **exit code จริง** (+ regex `expect` ที่ต้องพบ ถ้าตั้งไว้) — ไม่มี AI ตัดสินผ่าน/ไม่ผ่าน · fail-closed: `PASS` ได้ก็ต่อเมื่อ exit 0 และพบ `expect` · `NOEXPECT` (exit 0 แต่ไม่พบข้อความที่ต้องมี หรือไม่ตั้ง expect แต่ log บอกว่าไม่มีเทสต์ให้รัน) · `FLAKY` (ล้มแล้วผ่านตอนรันซ้ำ) · `TIMEOUT` · `CHANGED` (`HEAD` เปลี่ยนระหว่างทดสอบ) · `SKIPPED` · `ERROR` = ไม่ผ่านทั้งหมด · สถานะงาน `OK` เมื่อทุกชุด PASS และ HEAD ไม่เปลี่ยนเท่านั้น
- ตั้งชุดทดสอบใน `.flash.json` ของโปรเจกต์ (ทำงานกับโปรเจกต์ใดก็ได้ ไม่ผูกกับ flashq):
  ```json
  {"qa": {"presets": {"unit": {"cmd": "python -m pytest -q", "expect": "\\d+ passed", "timeout_min": 20, "retry": 1}, "lint": "ruff check ."}}}
  ```
  ช่อง: `cmd` · `expect` · `timeout_min` (ค่าเริ่มต้น `qa_timeout_min` = 30) · `idle_min` (ไม่ตั้ง = ปรับเอง: log เคยขยับ ≥ 5 ครั้งแล้วเงียบเกิน max(5 นาที, 6 × ช่วงเงียบนานสุด) **และ**โปรเซสทั้งชุด CPU/I/O นิ่งสนิทอีก 2 นาที = `HANG`→`TIMEOUT` · เงียบแต่ CPU ยังขยับ = ไม่ฆ่า · Windows · ระหว่างรัน flashq วัดชีพจรโปรเซสทั้งชุดทุก 20 วิ (`FLASHQ_QA_LIVE_POLL_SEC` · 0 = ปิด) ลง `job.qa_live` ให้หน้าเว็บโชว์ "โปรเซสขยับอยู่/นิ่งมา …" แม้สคริปต์ไม่พิมพ์ · ไม่ใช้ตัดสินฆ่า) · `retry` (0-3 · ค่าเริ่มต้น 1 = ล้มแล้วลองซ้ำ 1 รอบ · ผ่านเฉพาะรอบหลัง = `FLAKY` ไม่ผ่าน · 0 = ไม่ลองซ้ำ) · `cmds` (แทน `cmd`: รายการคำสั่ง/`{cmd,..}` ทำเป็นชุดย่อย `<ชื่อ>:<ไฟล์.py>` แยกผลทีละคำสั่ง ใช้ตัวเลือกอื่นร่วมกัน) · `cwd` (ใต้โปรเจกต์เท่านั้น) · `env_exit` (exit code ที่หมายถึง "สภาพแวดล้อมไม่พร้อม" เช่น `[3]` → ผล `ENV` 🔌: ยังนับว่าไม่ผ่าน แต่บอกชัดว่าไม่ใช่โค้ดผิด · ไม่ลองซ้ำ · ไม่เรียก Flash) · ยังไม่มีชุด → `flashq qa` บอกสิ่งที่เดาได้จากไฟล์ในโปรเจกต์ (ไม่รันเอง) · เจอ `tests/ui_*.py` ที่ import playwright → แนะนำชุด `ui` (ทดสอบหน้าเว็บด้วย Chrome headless: ไม่มีหน้าต่าง ไม่แย่งเมาส์ · ตัวอย่าง `tests/ui_smoke.py` · ไม่มี playwright = exit 3 → `ENV`)
- **คำสั่งมาจาก `.flash.json` หรือ `--cmd` ใน CLI เท่านั้น** — หน้าเว็บเลือกได้แค่ชื่อชุดที่มีอยู่ (ไม่รับคำสั่งสด กัน CSRF) · ค่าที่ผิด (ชื่อชุด/regex/timeout/cwd/JSON พัง) = แจ้งตั้งแต่ก่อนสร้างงาน ไม่ทิ้งงานค้าง
- Flash (agent `flash-tester` อ่านอย่างเดียว) เข้ามา**เฉพาะตอนล้ม** เพื่ออ่าน log อธิบายสาเหตุ — เป็นความเห็น ไม่เปลี่ยนคำตัดสิน · ปิดด้วย `--no-analyze` (ไม่เรียกโมเดลเลย)
- ตัวจัดคิว: นักทดสอบไม่รันคู่กับงานที่แก้ไฟล์ในโปรเจกต์เดียวกัน และไม่รันคู่กับนักทดสอบอีกตัวของโปรเจกต์เดียวกัน · ไม่ชนงานอ่านอย่างเดียว (ตรวจ/สืบ)
- ข้อจำกัด: ทดสอบ **checkout หลัก** ของโปรเจกต์ (worktree ถูกแปลงเป็น checkout หลัก) → ผลงาน Flash ต้อง merge เข้าก่อน แล้วใส่ `--commit <sha>` ยืนยัน · ตรวจเฉพาะ `HEAD` เปลี่ยนระหว่างรัน (ไฟล์ที่ยังไม่ commit แก้ระหว่างรันไม่ถูกตรวจ แต่รายงานจำนวนไฟล์ค้าง)
- อ่านผลจาก log ได้ทั้ง UTF-8 / รหัสหน้าเครื่อง / **UTF-16** (PowerShell 5.1 `>`) — `expect` จึงไม่พลาดเพราะรหัสตัวอักษร
- ยกเลิกงานแล้วฆ่า process ทดสอบที่กำลังรันด้วย · `retry` ในหน้าเว็บคงชุดเดิม · หน้าเว็บมีโหมด "ทดสอบ" (🧪) เลือกชุด + ช่องปิดตัวอธิบาย
- Claude Code: `/flash-qa [ชุด...]` (ติดตั้งด้วย `flashq.py install`) — รายงานตาม `QA=` ห้ามบอกว่าผ่านเมื่อไม่ใช่ PASS

- ไฟล์ที่ commit ของแต่ละงาน (hash ใน §4 ของแผน) แตะ ต้องอยู่ในรายการที่แผนอนุญาต (path ใน ` บนบรรทัดหัวงาน `- [x] **T-xx** …` + บรรทัด `ไฟล์:`/`แก้ไฟล์:` ใต้หัวงาน) · ไฟล์แผนเอง (ติ๊ก [x] + เติม §4) ผ่านเสมอ
- §4 ไม่มี hash จริง (worker ใส่ hash ของ commit ตัวเองไม่ได้ จึงมักเหลือ `(HEAD)`) → flashq หา commit เอง: ① commit ในช่วง `head0..head1` ของงานที่ flashq รันเอง (จดใน job record) ② ถ้าไม่มี → ตั้งแต่ `base commit` ในหัวแผน (ต้องเจอ commit เดียว ไม่งั้น NOCOMMIT) · commit ต้องมี `T-xx` แบบเต็มคำในข้อความ/trailer `Flash-Task: T-xx` (T-01 ไม่ชน T-01R) · `--fill` เติม hash ที่หาได้ลงช่อง commit ของแถว §4 เมื่อทุกงานผ่าน (ไม่ commit ให้)
- ผลต่องาน: `SCOPE T-xx OK|EXTRA|NOCOMMIT|NOFILES` · สุดท้าย `SCOPE_RESULT=PASS|FAIL` · exit 0 = PASS · 1 = ไม่ผ่าน · 2 = อ่านแผนไม่ได้/ไม่ใช่ git
- แผนไม่มีงาน T-xx = SCOPE NOTASK → FAIL
- กฎเฉพาะโปรเจกต์เป็นตัวเสริมใน `.flash.json`: `{"scope": {"always_ok": ["docs/plans/*.md"]}}` (glob ของไฟล์ที่แตะได้เสมอ) · ผู้ตรวจ (`flash-verifier`) รันคำสั่งนี้เป็นข้อแรก

### งานเอกสาร (doc) — ช่างเอกสารอัปเดตเอกสารให้ตรงกับโค้ด
```
python D:\MyCode\flashq\flashq.py doc [ชุด] [--since <commit/tag>] [--project P] [--timeout-min N]
python D:\MyCode\flashq\flashq.py doc-review <job> accept|discard [--force]
```
- Flash (agent `flash-writer`) อ่านโค้ดที่เปลี่ยนแล้ว**แก้ไฟล์เอกสารจริงใน checkout** — ได้เฉพาะ path ที่ชุดอนุญาต · **ไม่ commit ให้** · ผลเป็น "ร่าง" รอคุณดู diff แล้วรับ/ทิ้ง
- ตั้งชุดใน `.flash.json` ของโปรเจกต์ (ทำงานกับโปรเจกต์ใดก็ได้):
  ```json
  {"doc": {"presets": {"docs": {"paths": ["README.md", "CHANGELOG.md", "docs/**"], "brief": "เอกสารเป็นภาษาไทย · CHANGELOG เพิ่มบรรทัดใหม่ด้านบน", "timeout_min": 30}}}}
  ```
  ช่อง: `paths` (glob ใต้โปรเจกต์ 1-32 รายการ · `**`/`*` เดี่ยว ๆ หรือที่ครอบ `.git` `.flash.json` `.env*` กุญแจ = ปฏิเสธตั้งแต่เริ่ม) · `brief` (โจทย์เพิ่มเติม ไม่เกิน 4000 ตัวอักษร) · `timeout_min` (ค่าเริ่มต้น `doc_timeout_min` = 30) · มีชุดเดียว = ไม่ต้องระบุชื่อ
- **flashq ตัดสินเองจากไฟล์จริง** (fail-closed — ไม่เชื่อคำบอก "แก้เสร็จแล้ว" ของโมเดล): ผ่านได้ทางเดียวคือ `DRAFT` (ผ่านทุกด่าน รอผู้ใช้ตัดสิน) · อย่างอื่นไม่ผ่านหมด:
  - `REMOVED` = ลบ/แก้ทับเกิน `max_removed` (ค่าเริ่ม 40 · 0 = ปิด)
  - `OUTSIDE` แตะไฟล์นอกขอบเขต/ไฟล์ต้องห้าม · `SECRET` พบข้อความคล้ายรหัสผ่าน/โทเค็นในส่วนที่เพิ่ม → **flashq ย้อนไฟล์ให้ทันที**
  - `BADREF` เอกสารอ้างไฟล์ที่ไม่มีจริง · `DELETED` ลบไฟล์ · `UNCHECKED` ตรวจเนื้อหาไม่ได้ (ไบนารี/ใหญ่เกิน 1 MB) · `CHANGED` HEAD เปลี่ยนระหว่างรัน · `NOCHANGE` ไม่มีไฟล์เปลี่ยน · `TIMEOUT`/`ERROR` · `CANCELLED` → **เก็บไฟล์ไว้ให้ดู** แล้วรอคุณทิ้ง
- `--since` = เทียบโค้ดตั้งแต่ commit/tag นั้น · ไม่ระบุ = ตั้งแต่ครั้งล่าสุดที่ "รับ" ร่างของชุดนี้ · ไม่เคย = ให้ Flash ดูประวัติล่าสุดเอง
- **รับ** = เก็บไฟล์ไว้ (คุณ commit เอง) · รับได้เฉพาะ `DRAFT` · **ทิ้ง** = ย้อนเฉพาะไฟล์ที่ช่างเอกสารแตะ (ไฟล์ที่คุณแก้ค้างอยู่ก่อนรันคืนจากที่สำรองไว้ใน `~/.flashq/docbak/<job>`) · ปฏิเสธเมื่อ HEAD เปลี่ยนแล้ว หรือไฟล์ถูกแก้ต่อหลังช่างเอกสารจบ (`--force` ยืนยันทับ)
- ตัวจัดคิว: ช่างเอกสารไม่รันคู่กับงานที่แก้ไฟล์ นักทดสอบ หรือช่างเอกสารอีกตัวของโปรเจกต์เดียวกัน (ไม่งั้นแยกไม่ออกว่าใครแก้ไฟล์ไหน) · ไม่ชนงานอ่านอย่างเดียว (ตรวจ/สืบ) · ยกเลิกกลางทางแล้ว `flashq cancel` บอกไฟล์ที่แก้ค้าง
- ข้อจำกัด: ตรวจ `BADREF` เฉพาะ path ใน `` `...` `` ที่ขึ้นต้นด้วยโฟลเดอร์ + นามสกุล (ชื่อไฟล์ที่มีสระ/วรรณยุกต์ไทยไม่ถูกตรวจ) และตรวจแค่ว่าไฟล์มีจริง ไม่ได้ตรวจว่าเนื้อหาถูก → **ต้องอ่าน diff เทียบกับโค้ดก่อนรับเสมอ**
- ขอบเขตมาจาก `.flash.json` เท่านั้น — หน้าเว็บเลือกได้แค่ชื่อชุด (ไม่รับ path สด กัน CSRF) · หน้าเว็บมีโหมด "เอกสาร" (📝) + ปุ่ม ดู diff / รับ / ทิ้ง บนการ์ดงาน · `retry` คงชุดเดิม
- Claude Code: `/flash-doc [ชุด]` (ติดตั้งด้วย `flashq.py install`) — ตรวจ diff เทียบโค้ดจริงก่อนรายงาน · ห้ามรับ/ทิ้งเองจนกว่าผู้ใช้สั่ง

  - คลิกตัวละคร/การ์ด/แถวคิว = ไปดู log สดของงานนั้น · เปิดจากออฟฟิศแล้วมีปุ่ม 🏢 กลับออฟฟิศ ในแถบ log
  - **ผังโต๊ะ**: ≤5 ช่องอยู่แถวเดียว (6+ ช่อง = หลายแถว แถวละเท่า ๆ กัน) · จอแคบ = ย่อโต๊ะทั้งชุดแทนการล้น

  - **ปุ่ม "↩ session ต้นทาง"** (ในแถบเดียวกัน): กด = `POST /api/open_claude` → เปิด `claude://code/continue?session=local_…` ให้แอป Claude desktop เปิด session ที่สั่งงานนั้น · `local_…` มาจาก `claude_host` (งานใหม่เก็บ `CLAUDE_CODE_HOST_SESSION_ID` ตอนสั่ง) หรือไล่หา `cliSessionId` ใน `%APPDATA%\Claude\claude-code-sessions\*\*\local_*.json` (งานเก่า · ตั้งที่อื่นด้วย `FLASHQ_CLAUDE_APP_HOME`) · ชื่อที่แสดงใช้ `title` จากไฟล์นั้นก่อน ไม่มีค่อยใช้ transcript · รับเฉพาะรูปแบบ `local_[A-Za-z0-9-]` · ไม่พบ/สั่งจาก CLI = ข้อความบอกสาเหตุ ไม่เปิดอะไร
  - **แถบขั้นบนการ์ดงาน**: งานของเป้าหมาย = เขียนแผน → Flash ทำ → รอตรวจ → ตรวจ → ผล + "ตรวจแล้ว n/max รอบ · กำลังทำรอบ X · ผ่าน x/y เกณฑ์" · งานแผนทั่วไป = 🕵️ สืบ → ✍️ แผน → 🧑‍💻 Flash ทำ → 🔍 ตรวจ → 🏁 ผล + งานที่เกี่ยวข้อง: รอบที่เคยรันแผนนี้ · ผู้ตรวจ (verify) · ป้าย Claude ตรวจ · ผู้สืบ (**เดาจากเวลา**: งานสืบโปรเจกต์เดียวกันที่จบภายใน 6 ชม. ก่อนแผนนี้รันครั้งแรก — ผู้สืบไม่ได้ผูกกับแผนจริง)
  - **ป้ายไม่ค้าง/ไม่หลอก**: log หลักเงียบแต่ผู้ช่วยย่อย (subagent) ยังทำ = บรรทัด 🛠 ชื่องาน · tool ล่าสุด · ขยับเมื่อไร (ไม่เตือน "log เงียบ") · เวลาฆ่าของยามเป็นนาฬิกา + "ครบเวลาแล้ว รอยืนยัน" · ป้ายยามเก่ากว่า 180 วิไม่แสดง · แดชบอร์ดมีแถว "ความเคลื่อนไหว" (log หลัก · ผู้ช่วยย่อย · ยาม)
  - **หน้าแรกคือออฟฟิศ** (ถ้าเคยเลือกมุมมองไว้ จะจำค่าเดิม) · แถวคิวมีปุ่ม **รันเลย** (กล่องตรวจไฟล์ซ้อนเดิม · ซ้อน = ต้องติ๊กยืนยัน) และ **ยกเลิก** ใช้ได้จากหน้านี้เลย
  - **แผง 👔 หัวหน้า · ใบสั่งงาน**: จัดกลุ่มงาน (ช่องรัน + คิวรอ + เป้าหมาย) ตาม session Claude ที่สั่ง · ไม่มี session = "ไม่ทราบผู้สั่ง" · แต่ละรายการบอกบทบาท + สถานะ ทำ/รอ/รอตรวจ · ไม่มีงาน = ซ่อนแผง
  - **ป้ายบทบาทบนการ์ดงาน** (ช่างโค้ด · ผู้ตรวจ · ผู้สืบ · นักทดสอบ · ช่างเอกสาร) · รายละเอียดทางเทคนิคพับไว้ใน "รายละเอียดทางเทคนิค" (หัวพับเปลี่ยนสีเมื่อ log เงียบ — เตือนยังเห็นแม้พับ)
  - **ตาราง "เพิ่งจบ"**: ปุ่ม เปิด Claude/คัดลอก/สั่งซ้ำ ท้ายแถว · ผลช่างเอกสาร (DRAFT · รอคุณตัดสิน · ปุ่มรับ/ทิ้งร่าง) และผลนักทดสอบรายชุด · หัวตารางสรุป 👀 รอคุณตรวจ N (งานในตาราง 8 แถวแรก + เป้าหมาย)
  - **เปิด log จากออฟฟิศ** มีปุ่ม 🏢 กลับออฟฟิศ ในแถบ log กลับได้ทันที
  - "วันนี้จบแล้ว" ไม่นับงานที่ถูกยกเลิก/BUSY/รอคิวเกิน (ให้ตรงกับสถิติ)
  - **วิธีอ่านภาพ** เหลือ 4 บรรทัดหลัก (โต๊ะ · แถวซ้าย · โซฟา · ธง) · ศัพท์ละเอียด (สีเสื้อ · ผู้ตรวจ · ยาม · ท่าทาง ฯลฯ) พับไว้ใน "ศัพท์ละเอียด" · แผงนี้พับเป็นค่าเริ่มต้น
- ฟอนต์ปรับตามความกว้างจอ (1080p/2K/4K) + ปุ่ม **A− / 100% / A+** (หรือ `+` `-` `0` · Ctrl+วงล้อ · จำค่าในเบราว์เซอร์) · จอกว้างจัดเป็น 3 คอลัมน์ (งาน · log · บัญชี/สถิติ) และลดคอลัมน์เองเมื่อขยาย
- ทุกแผงพับได้ (จำไว้) · คิว/ประวัติ/log/สถิติกด ⛶ ขยายเต็มจอ (`Esc` ออก) · ประวัติ/log ลากมุมปรับความสูง · ประวัติค้นหา + กรองสถานะ/โปรเจกต์
- log: ค้นหา (กรองบรรทัด + ไฮไลต์) · ตัดบรรทัด · เลื่อนตาม · คัดลอก
- แจ้งเตือน (Notification ของเบราว์เซอร์ · ไม่อนุญาต = แสดงในหน้าแทน) เมื่องานจบเป็น OK/FAIL/QUOTA/TIMEOUT/NOSTART · ชื่อแท็บแสดงเวลางานที่กำลังทำ
- สถิติต่อโปรเจกต์/บัญชี (จำนวน · % ผ่าน · เวลาเฉลี่ย) · **ล้างประวัติ + log เก่า** (ตรวจก่อนแล้วยืนยัน · ไม่แตะงานรอคิว/กำลังทำ) = `python flashq.py prune --days 30 [--dry]`
- ปุ่มที่เปลี่ยนสถานะ (POST) ต้องผ่าน Host/Origin = 127.0.0.1/localhost + token สุ่มต่อการรัน (ฝังในหน้า) กัน CSRF · 403 แยกสาเหตุ: token หมดอายุ (`code: token` — server รีสตาร์ต/เปิดหน้านานเกินไป) กับ Host/Origin ไม่ตรง (ให้เปิดผ่าน 127.0.0.1/localhost) · `/api/state` ส่ง `boot` (รหัสรอบ server) → หน้าเว็บเทียบแล้วขึ้นป้าย "server รีสตาร์ตแล้ว" พร้อมปุ่มโหลดหน้าใหม่

ตัวเลือกที่ใช้บ่อยของ `run`: `--switch-on-quota 4` (โควตาหมด → สลับบัญชีถัดไปแล้วสั่งซ้ำเอง · งานที่ติ๊ก `[x]` แล้วจะถูกข้าม) · `--wait-min 720` (รอคิวได้นานสุด) · `--no-wait` · `--attach none` (ไม่ดูสด) · `--no-open`

ผลลัพธ์: บรรทัด `FLASH_RUN=OK|OK_UNVERIFIED|FAIL|DENIED|QUOTA|TIMEOUT|NOSTART|BUSY|QUEUE_TIMEOUT` + `job=<id>` · exit 0 = OK · 2 = BUSY · 3 = รอคิวเกินเวลา · อื่น ๆ = 1

`NOSTART` = opencode ไม่ขึ้น sessionID ใน log ภายใน 60 วิ (รอบลองใหม่ 120 วิ · ลองใหม่เอง 2 ครั้ง · `--retry-nostart` · วัดจริง: เริ่มได้ p50 6 วิ · p99 112 วิ) — flashq อ่านท้าย log กลางของ opencode (`~/.local/share/opencode/log/opencode.log`) หารอบที่เปิดโฟลเดอร์โปรเจกต์นี้ แล้วพิมพ์ `NOSTART รอบ n: …` ว่าค้างหลังบรรทัดไหน (เช่น `init` ก่อนสร้าง session = รออ่าน stdin ที่ไม่ปิด — flashq ปิดให้แล้ว · `llm runtime selected` = ผู้ให้บริการไม่ตอบ · ไม่นับรอบของงานอื่นที่เปิดโฟลเดอร์เดียวกันซึ่งโมเดลตอบแล้ว) และ `REASON:` ท้ายผล · ฐานข้อมูล `opencode.db` ใหญ่ ≥ 5 GB เตือนเพิ่ม · เก็บใน job (`nostart_diag`, `last`) · ไม่เจอรอบเลย = process ไม่ทันบูต

## `.flash.json` (ทุกช่องไม่บังคับ · `main_branch`/`remote` ไม่ตั้ง = ตรวจจาก git · `flashq init` สร้างให้)
```json
{
  "main_branch": "master",
  "remote": "origin",
  "require_plan_in_remote": true,
  "command": "flash",
  "timeout_min": 480,
  "rules": "กติกาเพิ่มที่ /flash แบบ global ต้องทำตาม (เช่น คำสั่ง commit ของโปรเจกต์)",
  "external_dirs": ["D:/MyCode/my-game/*"],
  "open_session": false
}
```
- `open_session` (true/false · ไม่ใส่ = ตามเครื่อง) = เปิดหน้าต่าง session ของพนักงานตอนงานเริ่มไหม เฉพาะโปรเจกต์นี้ · ลำดับ: `--no-open` > `.flash.json` ของโปรเจกต์ > `flashq config open_session on|off` ของเครื่อง (หรือสวิตช์ "หน้าต่าง session" บนหน้าเว็บ) > ค่าเริ่มต้นตามผู้สั่ง · `auto` (ล้างค่าเครื่อง) = งานที่ส่งด้วย `run --detach` (เช่น จาก opencode) **ไม่เปิด** นอกนั้นเปิด · งานที่ส่งจากหน้าเว็บ (submitter ui) ไม่เปิดเหมือน --detach

### งานถูกปฏิเสธสิทธิ์ (DENIED)
- `opencode run` เป็นโหมดไม่โต้ตอบ: ถ้า agent แตะไฟล์**นอกโปรเจกต์**และ `permission.external_directory` ใน `~/.config/opencode/opencode.json` เป็น `ask` opencode จะตอบ "ไม่อนุญาต" ให้เองทันที (stderr: `permission requested: external_directory (<path>); auto-rejecting`) → subagent ล้ม งานจบ exit 0 โดยไม่ได้ทำอะไร
- flashq ตรวจ stderr + tool error นั้นแล้วให้ `FLASH_RUN=DENIED` (ไม่ใช่ OK) พร้อมบรรทัด `DENIED:` บอก path ที่ถูกปฏิเสธ + ทางแก้ 2 ทาง · `flashq wait` คืน exit 1 เหมือน FAIL · หน้าเว็บมีป้าย DENIED + 🚫 path บนแถวงาน + ทางแก้ในกล่อง log · ถ้าถูกปฏิเสธแต่มี commit ใหม่หรือ worker ตอบ `DONE` = สำเร็จบางส่วน → คง OK แต่พิมพ์ `WARN:` รายการที่ถูกปฏิเสธ
- **ทางแก้ 1 (แนะนำ)**: ใส่ `"external_dirs": ["D:/path/*", ...]` ใน `.flash.json` → ทุกครั้งที่รัน flashq ส่งสิทธิ์ให้ opencode ผ่าน `OPENCODE_CONFIG_CONTENT` (รวมกับ config ของผู้ใช้ตอนเริ่ม ไม่แตะไฟล์ `opencode.json`) · ไม่ใส่ `*` = เติม `/*` ให้ · ใช้ `/` หรือ `\\` ก็ได้
  - ข้อจำกัด `--attach live`: server สด (4096) โหลด config ครั้งเดียวตอนเปิด → flashq ส่ง `external_dirs` ของทุกโปรเจกต์ที่เคยส่งงานให้ตอน**เปิด** server เท่านั้น · เพิ่ม `external_dirs` ทีหลังต้องปิด server (`taskkill /PID <pid ใน ~/.flashq/live_server.pid> /T /F`) แล้วสั่งงานใหม่ flashq จะเปิดให้เองพร้อมสิทธิ์ใหม่ · ก่อนรัน flashq ถาม `/config` ของ server แล้วพิมพ์ `WARN:` ถ้ายังไม่ครอบ
- **ทางแก้ 2 (ถาวร)**: เพิ่มใน `opencode.json` ช่อง `permission.external_directory` เช่น `"D:\\MyCode\\my-game\\*": "allow"` (รูปแบบเดียวกับที่ opencode รายงาน · Windows = `\\`) แล้วรีสตาร์ต server สด
- ก่อนรันทุกครั้ง flashq พิมพ์ `PERM:`/`WARN:` บอกว่า `external_dirs` ถูกอนุญาตแล้วหรือยัง และเตือนถ้า `opencode.json` อ่านไม่ได้ (JSON เสีย เช่นลืมคอมมา — opencode จะเปิดไม่ขึ้น)

- ผู้วางแผน (`/flash-plan`) หาชื่อจากตาราง routing ใน `AGENTS.md`/`CLAUDE.md` ก่อน ไม่มีตารางค่อย `ls` `.opencode/skills/` · `.claude/skills/` (ไม่เปิด `SKILL.md`) · ไม่มี skill เลย = ข้าม
- `flash-worker` โหลดด้วย `skill` tool ก่อนลงมือ แล้วรายงานบรรทัด "skill ที่โหลด" · หาไม่เจอ = `FAIL: ไม่พบ skill` · `flash-investigator` โหลดเมื่อบรีฟระบุหรือตาราง routing ชี้ skill สืบบั๊ก · `flash-checker` ตรวจว่ารายงานมี skill ตรงชื่อ
- `flashq run` เตือน (`WARN`) ถ้าชื่อไม่ตรง skill ที่มีใน `.opencode/skills` · `.claude/skills` ของโปรเจกต์ หรือ `~/.claude/skills` · `~/.config/opencode/skills` · `~/.agents/skills` (ไม่บล็อกการส่งงาน)

## เทสต์ (ใช้ opencode ปลอม ไม่เรียกโมเดลจริง)
```
python -W ignore tests\test_flashq.py
```
หรือ `python -m pytest tests/test_flashq.py -q` (ทั้งชุดใช้เวลาราว 6 นาที · เลือกบางข้อด้วย `-k <คำ>`) · เทสต์ตั้ง `FLASHQ_HOME` เป็นโฟลเดอร์ชั่วคราวเอง ไม่แตะ `~/.flashq` จริง
